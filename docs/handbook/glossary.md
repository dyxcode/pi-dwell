Session, turn, run, native execution, event sequence, and history cursor name distinct records or identifiers, even when they appear together in the UI or API.

## Product and runtime

| Term | Meaning in Dwell |
| --- | --- |
| **Dwell** | The local host and browser client in this repository. Dwell keeps its own session/turn catalog, starts Pi processes, translates runtime activity into a bounded HTTP/SSE protocol, and projects Pi's saved history. It is not a second model runtime. |
| **Pi** | The installed `@earendil-works/pi-coding-agent` package and executable used by Dwell. Pi owns model/provider behavior, its native session format, and extension/native execution. Dwell talks to the configured executable through the supported Pi 1.4.0 RPC protocol. |
| **Host** | The Node process serving Dwell's loopback HTTP interface and owning the active in-memory session service. The host can stop while the SQLite catalog and Pi JSONL files remain on disk. |
| **Pi process / runtime** | A live child process speaking Pi RPC for a Dwell session or for isolated model discovery. A Dwell session can remain stored while its runtime is closed. |
| **Pi RPC** | Pi's newline-delimited JSON request/response/event protocol over the child process's stdin/stdout. Dwell correlates command responses by generated RPC ID; RPC IDs are transport details, not Dwell request, turn, or native execution IDs. |

## Sessions, turns, and identifiers

| Term | Meaning and distinction |
| --- | --- |
| **Dwell session** | A durable Dwell record tying together one project directory, a Pi session identity/native file, the selected provider/model/thinking level, and Dwell's turns. Closing it stops the live runtime; it does not mean deleting the record or transcript. |
| **Dwell session ID (`session.id`)** | The UUID used by Dwell routes, session records, turns, saved-history responses, and stream frames. It is generated by Dwell and remains the API-level session key. |
| **Pi session ID (`session.piSessionId`)** | The native session UUID recorded in Pi's JSONL session file. Dwell uses it to verify that a candidate file belongs to this Pi conversation. It is not interchangeable with the Dwell session ID. |
| **Session status** | Durable creation result: `creating`, `ready`, `failed`, or `interrupted`. It describes the Dwell session record. |
| **Runtime state (`runtimeState`)** | Current process lifecycle projection: `closed`, `opening`, `ready`, `failed`, or `closing`. It describes the live Pi child; a `ready` session may have a `closed` runtime when not open. |
| **History state (`historyState`)** | Dwell's view of saved transcript availability: `empty`, `available`, or `unavailable`. This says nothing by itself about whether a Pi process is open. |
| **Turn** | One durable Dwell-submitted prompt operation, with a `requestId`, generated `runId`, status, optional error, and the saved native entry IDs attributed to it. A turn is not the entire session transcript. |
| **Run ID (`runId`)** | The generated UUID identifying the durable turn record. Routes use it to read a result or request abort. It is distinct from both the caller's `requestId` and a Pi-native execution ID. |
| **Request ID (`requestId`)** | A client-supplied UUID used to make session creation and turn submission idempotent. Repeating the same ID and same payload retrieves the original operation; repeating it with changed settings/content yields `request_conflict`. It is not a run ID. |
| **Payload identity** | A SHA-256 identity stored privately with a session/turn request so Dwell can distinguish an exact retry from reuse of the same `requestId` for different settings, text, or images. Clients do not send or select this digest. |
| **Native execution** | Work initiated through Pi's native extension/UI path rather than a Dwell turn submission. Dwell observes its start/settlement and can request its abort using the current native execution ID. It has separate lifecycle/identity from the Dwell turn ledger. |
| **Native execution ID** | An ephemeral UUID created by Dwell's `PiProcess` adapter for one observed native execution. It is not durable across runtime replacement and does not identify a Dwell turn. Stale IDs are rejected rather than aborting whichever work happens to be current. |
| **Active turn** | The one Dwell turn currently in `accepted`, `dispatching`, or `running`. The SQLite partial unique index enforces at most one active Dwell turn per session. |
| **Latest turn** | The newest Dwell turn record, which may be terminal. “Latest” does not imply active. |

The session and turn contracts are in [`shared/sessions.ts`](../../src/shared/sessions.ts) and [`shared/turns.ts`](../../src/shared/turns.ts); durable records and indexes are in [`storage/catalog.ts`](../../src/storage/catalog.ts).

## Execution and recovery language

| Term | Meaning and distinction |
| --- | --- |
| **Accepted** | The durable turn row exists, but Dwell has not yet recorded that it crossed into dispatch. On host recovery, an accepted row can safely become `interrupted` with `not_dispatched`. |
| **Dispatch / dispatched** | Dwell durably writes `dispatching` before it calls Pi's `prompt` RPC. That marker is intentionally conservative: a crash after the write is treated as uncertain even if shutdown raced the actual RPC call. After this point an RPC break or host stop cannot prove whether the model executed it. |
| **Running** | Pi acknowledged the prompt as started; the turn remains active until its run settles or is interrupted. |
| **Settled** | Pi returned a final run outcome (`completed`, `failed`, `aborted`, or `handled`) and Dwell is recording the resulting state/history coverage. Settled means the runtime run ended, not necessarily that every saved-history projection was available. |
| **Interrupted / `outcome_unknown`** | A turn ended without a reliable live owner or final result after dispatch. It is terminal for the Dwell ledger. Dwell intentionally does not replay it automatically. |
| **`not_dispatched`** | Recovery classification for a durable `accepted` turn that never crossed the recorded dispatch boundary. It says the prompt was not sent by that turn. |
| **Handled prompt** | A Pi extension accepted and handled the prompt through Pi's extension flow rather than producing the ordinary prompt run outcome. Dwell reconciles the saved history and records completion separately from a standard model result. |
| **Turn cancellation** | A Dwell request to abort one identified run. `cancellationRequested` records the request; it does not alone prove that Pi stopped. Check the terminal status/outcome. |
| **Runtime closure** | Stopping the Pi child for a session. This is separate from aborting one turn/native execution and separate from closing/deleting the durable Dwell session record. |

The exact transition rules live in the [catalog](../../src/storage/catalog.ts); the prompt/abort coordination is in [SessionService](../../src/sessions/service.ts) and [PiProcess](../../src/runtime/pi-process.ts).

## Saved history, context, and branches

| Term | Meaning and distinction |
| --- | --- |
| **Pi session file / native history** | Pi's JSONL file containing native session metadata, entries, parent links, and branch selection. It is the source Dwell reads to build saved history; Dwell does not replace it with its own transcript format. |
| **Session catalog** | Dwell's SQLite `catalog.sqlite` records for runtime configuration, session identity/status, and turn state. It is not the Pi transcript and does not contain the full conversation messages. |
| **History entry** | One projected Pi-native JSONL entry. The API keeps the native entry ID and parent link and converts supported content into display blocks; a projection may mark content as truncated or unsupported. |
| **Branch** | The parent-linked path from the native session's selected leaf back to the root. The history page is built from that active path; the JSONL file may contain entries on other branches too. |
| **Leaf ID (`leafId`)** | The Pi entry ID currently selected as the native branch tip. It is not the Dwell session ID and can change when the Pi branch changes. |
| **Saved-history projection** | Dwell's bounded, paginated display representation of the active native branch. It is not guaranteed to equal the exact in-memory model context or to include every hidden/native field. |
| **Context (`GET …/context`)** | Pi's current runtime message list returned through `getMessages()`. It is a live-runtime view; the request opens or reopens the session runtime as needed. It is not the paginated saved transcript. |
| **Context sources** | A preview Dwell projects from Pi's saved system/compaction context metadata, such as instruction sources. It is distinct from both the `GET …/context` message list and the full user/assistant transcript; it can be truncated. |
| **History revision** | A SHA-256 fingerprint over the native file's device/inode identity and complete JSONL byte prefix. Dwell pins page cursors to a revision so pagination does not silently cross a changed file. |
| **History cursor (`nextCursor`)** | An opaque, signed pagination token for the same Dwell session, byte prefix, and saved-history revision. Its signing key belongs to the current service instance, so a restart can invalidate an old token. Pass it only as the history `cursor` query parameter. It is separate from SSE `Last-Event-ID`; reload the first page when rejected. |
| **Turn coverage (`coveredTurnId`)** | The latest terminal Dwell turn whose recorded entry IDs are all proven to exist on the saved active branch. A turn can be terminal before saved-history coverage becomes provable. |
| **Native-execution coverage** | `coveredNativeExecutionId` identifies a terminal native Pi execution proven present on the saved branch. It is a coverage marker, not an entry ID or a durable turn. |

The native file reader is [`pi-history.ts`](../../src/runtime/pi-history.ts); branch projection, signed page cursors, and context-source extraction are in [`sessions/history.ts`](../../src/sessions/history.ts). The response types are in [`shared/history.ts`](../../src/shared/history.ts).

## Events, snapshots, and cursors

| Term | Meaning and distinction |
| --- | --- |
| **SSE** | Server-Sent Events, the host-to-browser stream for snapshots and incremental session/turn/live-message/tool changes. The browser may reconnect using the most recently accepted event cursor. |
| **Snapshot** | A bounded point-in-time session/event projection used at initial connect or after resynchronization. It includes session and turn metadata plus the bounded live projection; it is not the full saved transcript. |
| **Event cursor** | A stream resume ID in the form `sessionId:epoch:sequence`. `epoch` identifies the current in-memory event stream generation, and `sequence` orders its frames. It is used in SSE `id`/`Last-Event-ID`, not in history pagination. |
| **Event epoch** | A server-generated UUID for one in-memory event-hub generation. If it changes, the server sends a `resync` frame and a fresh snapshot rather than replaying events from a different generation. |
| **Sequence** | The monotonically increasing number within one session's event epoch. It orders stream frames only; it is not a turn number or Pi JSONL entry ID. |
| **Replay window** | The bounded event history retained in memory for reconnects. If a cursor is ahead, stale, from another epoch, or outside the replay window, the server tells the client to resynchronize. |
| **Resync frame** | An SSE `resync` control frame explaining why incremental replay cannot continue (`cursor_stale`, `cursor_ahead`, `epoch_changed`, or `replay_limit`). It carries no ordinary event cursor and is not itself an error result. |
| **Live projection** | A bounded, transient view of the currently streamed assistant message and tools. It may be truncated and is not the authoritative saved-history record. |
| **Projection limit/error** | A stream event reporting that live metadata was capped or an incoming Pi event could not be converted. It describes the live view pipeline, not necessarily the persisted JSONL file or model outcome. |

Contracts are in [`shared/events.ts`](../../src/shared/events.ts); the per-session hub and cursor/replay rules are in [`sessions/events.ts`](../../src/sessions/events.ts); the bounded writer and browser decoder are [`server/sse.ts`](../../src/server/sse.ts) and [`clients/web/events.ts`](../../src/clients/web/events.ts).

## Model and diagnostic terms

| Term | Meaning in this repository |
| --- | --- |
| **Provider** | Pi's model-provider identifier, paired with a model ID. Dwell stores/displays the selection but does not define provider authentication semantics. |
| **Model ID** | Pi's model identifier within a provider. The same text under a different provider is a different selection. |
| **Model capability** | Discovered metadata for one provider/model pair, including whether it accepts images and the thinking levels it supports. |
| **Thinking level** | The Pi-supported preference in `off`, `minimal`, `low`, `medium`, `high`, `xhigh`, or `max`. Available values depend on model capabilities; it is not a turn status. |
| **Image support** | Capability metadata indicating whether the selected model can accept image input. Dwell validates this before dispatch and still bounds/validates image data at the request boundary. |
| **HTTP status** | The numeric response status such as 400 or 503. It describes the HTTP request outcome; it is separate from Dwell session/turn status strings. |
| **Error code** | A layer-specific diagnostic string in an HTTP error, turn record, or stream event. The same spelling can appear in more than one layer and does not always have an HTTP status. |
| **Pairing code** | A one-time short credential created by the local CLI for browser pairing. It is security-sensitive input, not an error code or request ID. |
| **Request/turn idempotency** | The guarantee that the same `requestId` and same payload refers to the original operation. It prevents duplicate creation/execution after retries; it does not cause Dwell to replay an uncertain Pi prompt. |

See [shared contracts](../../src/shared/sessions.ts), [thinking/model capabilities](../../src/shared/thinking.ts), and the [error reference](errors.md) for concrete status/code behavior.
