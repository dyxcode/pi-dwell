# Browser controller internals

English | [简体中文](../../i18n/zh-CN/handbook/implementation/browser-controller.md)

[`client.ts`](../../../src/clients/web/client.ts) coordinates browser controls for a Pi session through the host. It validates API payloads with shared guards, tracks drafts and generations, displays saved Pi history alongside current SSE observations, and submits host requests. The host manages the Pi process and reads the saved transcript from Pi’s native session history. The page contract and its renderer are explained in [Browser rendering](browser-rendering.md); SSE parsing/reduction and identity-based saved/live joining are in [Browser events](browser-events.md); input and image drafts are covered in [Browser input](browser-input.md). API paths below are relative to `/api/v1`.

<a id="dom-contract-coordinator-state"></a>
## DOM contract and coordinator state

[`el`](../../../src/clients/web/client.ts#L40) looks up a required element and throws if it is missing or has the wrong DOM class. [`node`](../../../src/clients/web/client.ts#L45) creates an element with `textContent` and a class name; it is used for dynamic labels and errors so server text is not parsed as HTML. At module load, the controller captures the shell controls, initializes [`setupComposer`](browser-input.md#composer-sizing-and-viewport-adaptation), creates one [`SavedConversationRenderer`](browser-rendering.md#saved-group-rendering-cache), and wires the model/image helper objects. The page’s IDs are defined in [`HOST_PAGE`](../../../src/clients/web/page.ts#L1).

The coordinator keeps independent state for the session catalog (`sessions`, `selected`), current SSE [`ConversationState`](browser-events.md#state-bounds-protocol-errors), saved history (`entries`, `nextCursor`, context), turn metadata, text drafts, image drafts, model capability caches, pending create/send requests, open/close dialogs, and connection timers. Invalidation counters fence work by owner: `authAttempt` invalidates requests from an older authentication attempt; `generation` fences stream, history, and image work when the selected session or page lifecycle changes; and `selectionGeneration` fences operations tied to the selected session. `sessionRefreshGeneration` and `sessionStateGeneration` protect catalog refreshes from overlapping refreshes and newer session updates. `openIntentGeneration`, `closePreparationGeneration`, and `closeAttemptGeneration` scope open/close operations, while `browseAttempt` and `modelAttempt` scope directory/model dialog reads. Callbacks check their captured counters after awaiting, so an old selection, login, or dialog response cannot overwrite current state. `pendingSend` and `pendingCreate` retain request IDs and payload choices across an uncertain response, while request states (`sending`, `historyPending`, `openingSessions`, `changingModel`, and `closingSession`) gate conflicting controls.

[`showImage`](../../../src/clients/web/client.ts#L185) sets the preview image’s source, alt text, and title before opening the image dialog. [`releaseImages`](../../../src/clients/web/client.ts#L241) revokes every resolved saved-image object URL when its promise settles, clears the request cache, increments `imageGeneration`, and invalidates saved-group render shells. These are separate from `Attachments` draft URLs, which are cleaned by the input module.

<a id="browser-http-transport"></a>
## Browser HTTP transport

The browser API wrapper lives in [`transport.ts`](../../../src/clients/web/transport.ts). [`ApiError`](../../../src/clients/web/transport.ts#L3) stores the HTTP status and host error code alongside its message; [`ApiError.constructor`](../../../src/clients/web/transport.ts#L6) initializes those fields. [`binding`](../../../src/clients/web/transport.ts#L12) reads the browser binding at `dwell.browser-binding.v1`, accepts only 64 lowercase hex characters, and optionally creates 32 cryptographically random bytes. It verifies that local storage retained the created value and maps any storage/crypto failure to a status-0 `storage` error. [`headers`](../../../src/clients/web/transport.ts#L33) always accepts JSON and adds `X-Dwell-Browser` when a valid binding exists. [`responseError`](../../../src/clients/web/transport.ts#L39) parses only the expected `{ error: { code, message } }` shape; malformed or unreadable bodies become a bounded generic `http` error with the response status.

[`api`](../../../src/clients/web/transport.ts#L60) sends same-origin JSON `GET` or `POST` requests with `cache: no-store`. A POST adds `Content-Type: application/json` and `X-Dwell-Request: 1`; credentials are `same-origin` only when a browser binding exists and otherwise omitted. GETs time out after 15 seconds, POSTs after 60 seconds. Successful JSON remains `unknown`, so the owning controller operation applies the corresponding shared runtime guard before using it. [`message`](../../../src/clients/web/transport.ts#L77) extracts a normal `Error.message` and supplies a generic message for non-Error throws. The fixed binding key is [`BINDING_KEY`](../../../src/clients/web/transport.ts#L2). Browser asset tests check that the compiled transport contains the expected binding and request headers and no Node imports or cookie-based credentials ([`web.test.ts`](../../../tests/web.test.ts#L16)).

Pairing is the one call that first creates the local binding: the pair-form handler posts the exact trimmed pairing code and browser key to `/auth/pair`, clears the code on success, and then calls `connect()`. Authentication remains host-side; the browser stores no provider credential. A 401 from any operation enters the same disconnect path.

<a id="model-capability-state-image-gate"></a>
## Model capability state and image gate

Capability cache entries are keyed by the tuple `[sessionId, provider, model]`. [`resetCapabilities`](../../../src/clients/web/client.ts#L86) increments `capabilityGeneration` and clears successful results, in-flight request sharing, and failed checks. [`activeSession`](../../../src/clients/web/client.ts#L331) resolves the selected catalog item. [`savePreference`](../../../src/clients/web/client.ts#L323) updates the in-memory preference object and attempts to persist it as `dwell.web.preferences.v1`; storage failure leaves the in-memory UI usable. Startup accepts only string preference values up to 200 characters, and `select()` saves the selected session ID. [`modelCapabilityKey`](../../../src/clients/web/client.ts#L334) returns a stable tuple key only when all three identity parts are available.

[`requestModelCapabilities`](../../../src/clients/web/client.ts#L343) returns a cached result or existing promise before making a new request, so concurrent UI actions for the same session/model share one host read. It posts provider/model to `/sessions/{id}/model-capabilities`, validates the response and its provider/model identity, caches it only if its generation is still current, records failures only for that generation, and removes only its own in-flight promise in `finally`. It rerenders navigation as checking begins and ends. [`probeCurrentModel`](../../../src/clients/web/client.ts#L383) runs only when authenticated and the session’s Pi process is ready with a selected provider/model. It avoids duplicate or failed probes and reports only a still-current 401.

The image-button callback initially supplied to `Attachments` is replaced by the controller’s guarded handler. It allows the picker when the selected model is already confirmed to support images; if a capability read previously failed, it retries and opens the picker only if authentication, selection, generation, provider/model, and support result still match. Navigation disables new intake while support is unknown, pending, failed, or false, while existing attachments remain removable. `submit()` performs a final known-negative capability check before sending. A failed probe keeps new image intake disabled until support is confirmed.

<a id="session-labels-status-navigation"></a>
## Session labels, status, and navigation

[`label`](../../../src/clients/web/client.ts#L411) composes the locally remembered display name (or final directory component), model ID, and optional thinking level. [`runtimeOpen`](../../../src/clients/web/client.ts#L418) means the Pi process state is anything except `closed`; the tab logic therefore treats `opening`, `ready`, `failed`, and `closing` sessions as open. [`nativeRunning`](../../../src/clients/web/client.ts#L421) returns the ID only for an actively running Pi-native extension execution. [`sessionBusy`](../../../src/clients/web/client.ts#L424) combines that lane with a Dwell active turn.

[`status`](../../../src/clients/web/client.ts#L427) gives native execution status precedence when present; otherwise it resolves the selected session from live reducer state and other sessions from the local turn cache, then maps active, interrupted, failed, aborted, opening/creating, completed, and idle states to user-facing labels. [`TabStatus`](../../../src/clients/web/client.ts#L449) is the compact visual category, and [`tabStatus`](../../../src/clients/web/client.ts#L450) and [`tabStatusLabel`](../../../src/clients/web/client.ts#L458) map those textual states to the five tab styles and accessible descriptions. `statusPaths` supplies fixed SVG paths; [`tabSymbol`](../../../src/clients/web/client.ts#L481) creates an aria-hidden icon from them.

[`synchronizeTabSlots`](../../../src/clients/web/client.ts#L497) keeps existing slot numbers for still-open sessions, drops slots for closed sessions, and assigns each new open session the lowest free positive number. [`openTabIds`](../../../src/clients/web/client.ts#L509) returns catalog order for open tabs. [`closeBlockedReason`](../../../src/clients/web/client.ts#L512) prevents close preparation while unauthenticated or while send, uncertain send, model change, image intake, creation, or another open operation is pending.

[`showError`](../../../src/clients/web/client.ts#L522) routes a 401 into `disconnect()` because the browser pairing is no longer valid; other errors appear in the live notice region. [`clearNotice`](../../../src/clients/web/client.ts#L530) clears that region. [`nav`](../../../src/clients/web/client.ts#L534) opens/closes the mobile drawer, coordinates `inert`, scrim and `aria-expanded`, and moves keyboard focus to the correct navigation button.

[`navigation`](../../../src/clients/web/client.ts#L543) is the derived-UI pass. It rebuilds sidebar rows for every catalog session and status tabs for sessions whose Pi process is not closed, then calls `reconcileChildren` so stable session/tab nodes survive rerenders. The nested [`navigation.slotNumber`](../../../src/clients/web/client.ts#L549) formats the persistent slot map. A sidebar activation calls `openFromSidebar`; a status tab selects its session, while a second activation on the selected tab arms its close control. The pass also updates the selected directory/model labels and computes whether model choice, text input, image intake, and send/stop/retry are enabled from authentication, Pi-process state, active turn, model probe, draft, and request state. It sets accessible labels and tooltips alongside disabled properties.

<a id="opening-closing-concurrency-checks"></a>
## Opening, closing, and concurrency checks

[`updatedSession`](../../../src/clients/web/client.ts#L719) replaces or appends a catalog entry, increments `sessionStateGeneration`, and returns the open-tab order from before that change. [`neighborAfterClose`](../../../src/clients/web/client.ts#L729) selects the next still-open tab after the closed one, then searches backward, then falls back to the first open session. [`reconcileClosedRuntime`](../../../src/clients/web/client.ts#L744) reacts when the selected session’s Pi process is closed elsewhere, closes a now-obsolete confirmation dialog when appropriate, reports that another browser closed it, and selects a neighbor.

[`userMessageSnippet`](../../../src/clients/web/client.ts#L753) finds the latest saved user entry, joins its text blocks, normalizes whitespace, and keeps at most 100 Unicode characters for the close confirmation. [`showCloseError`](../../../src/clients/web/client.ts#L766) displays an error inside that dialog.

[`prepareClose`](../../../src/clients/web/client.ts#L770) runs only for the currently selected open session and only when no competing operation blocks closing. It captures authentication, selection, state, and preparation generations; reads fresh session metadata and the latest history page concurrently; then rechecks all captured conditions before displaying a confirmation. If another state update landed while those requests were in flight, `sessionSnapshot` performs a fresh read rather than trusting the earlier one. The dialog records the exact active Dwell run ID or running native execution ID that the user reviewed. It can therefore label the operation “Stop and close?” and avoid stopping a newly started response without a new confirmation. History failure does not prevent the confirmation unless it is an authentication failure.

[`sessionSnapshot`](../../../src/clients/web/client.ts#L854) and [`turnSnapshot`](../../../src/clients/web/client.ts#L860) validate both shape and requested identity. [`turnIsActive`](../../../src/clients/web/client.ts#L866) recognizes accepted, dispatching, and running turns. [`waitForTurnAndRuntime`](../../../src/clients/web/client.ts#L869) polls the exact run and session every 250 ms for up to 60 seconds; it stops if authentication changes, a different response starts, the Pi process closes, or both the turn and active-turn pointer settle. [`finishClose`](../../../src/clients/web/client.ts#L894) closes the dialog, clears the armed state, and selects a neighboring open session if the closed one was selected.

[`confirmSessionClose`](../../../src/clients/web/client.ts#L900) is one-shot per reviewed `closeTarget`. It first refreshes the session and then follows the captured lane: a native execution is aborted by its native execution ID and checked every 150 ms for up to 15 seconds; a Dwell active turn is re-read, aborted if needed, and awaited through `waitForTurnAndRuntime`; an apparently idle target is read again before close. Any different/new run interrupts the close attempt and requires review again. Only a settled session reaches `/close`. If a response is ambiguous or fails, the dialog retains its error and the controller refreshes authoritative state; if the session’s Pi process has already closed, selection finishes without repeating the close mutation. Generation checks, disabled confirmation controls, and the `attempted` flag prevent concurrent or duplicate operations. The close dialog’s `cancel`/`close` listeners delegate to [`dismissCloseDialog`](../../../src/clients/web/client.ts#L2130) and [`resetCloseDialog`](../../../src/clients/web/client.ts#L2117), which clear the captured target, restore buttons and focus, and account for queued native dialog close events.

[`openFromSidebar`](../../../src/clients/web/client.ts#L1012) requires authentication and completed image intake. A session whose Pi process is neither closed nor failed is selected directly. A closed or failed Pi process is started through `/sessions/{id}/open`; the response is validated and selected only if the open intent, selection generation, and authentication are still current. Per-session `openingSessions` prevents duplicate starts, and `finally` always removes the opening marker.

<a id="conversation-rendering-saved-images"></a>
## Conversation rendering and saved images

[`identifyLiveThinking`](../../../src/clients/web/client.ts#L1048) upgrades currently rendered live thinking disclosures to their confirmed native message/content identity when a final message or snapshot provides it. That identity matches `thinkingDisclosureKey` in the saved renderer, preserving disclosure state across live-to-saved handoff.

[`historyImage`](../../../src/clients/web/client.ts#L251) returns a loading button immediately and requests the saved image at the selected session, entry ID, and image index. Requests are serialized through `imageQueue`, deduplicated in `imageCache`, sent with browser-binding headers, and bounded by a 15-second timeout and 5 MiB blob cap. The response content type must equal the history block’s MIME. Selection/generation checks discard late responses. A successful blob becomes an object URL; `onload` inserts the image only while its placeholder remains connected and preserves a near-bottom scroll position. Clicking previews it through `showImage`. A fetch/blob/cache rejection leaves a retry button that drops the failed cache entry, invalidates cached render shells, and rerenders; a 401 is routed through authentication handling. If the fetched object URL is assigned but the browser’s image decoder raises `onerror`, the placeholder changes to “Saved image cannot be displayed.” without a retry action or cache reset.

[`renderConversation`](../../../src/clients/web/client.ts#L1060) builds the desired conversation fragment before reconciling it with the current DOM. Before rendering, it records whether the user is near the bottom, the focused disclosure key, currently open disclosure keys, and a visible entry/key scroll anchor. With no selected session it renders an empty state. With a selection it appends cached saved history/context, restores disclosure state, and adds a separate live response only while the history page has not covered that run. `visibleLiveContent` removes live items already present in saved history by native identity, not equal text. When server order metadata is absent, the controller uses its bounded observation-order list. Live messages render ordered text/thinking blocks; live tool disclosures show parsed bash summaries where possible, partial input/output, and current status. Turn/native errors and history retry states render alongside the conversation. After `reconcileChildren`, it restores focus if the old disclosure was replaced, keeps the viewport pinned only if the reader was already at the bottom, otherwise adjusts scroll to keep the chosen anchor at its previous screen position. The message and tool DOM shapes are detailed in [Browser rendering](browser-rendering.md#saved-group-rendering-cache).

<a id="saved-history-recovery"></a>
## Saved history and recovery

`historyRecovery.latest` and `.older` keep independent failure counts and retry timers, while `historyPending` enforces one browser history request at a time. [`historyProblem`](../../../src/clients/web/client.ts#L1246) chooses whether to show a latest-content or older-page retry state. [`resetHistoryRecovery`](../../../src/clients/web/client.ts#L1250) cancels selected retry timers and clears failure/queued flags; a latest reset also clears coverage tracking and the current content-failed latch. [`uncoveredHistoryRun`](../../../src/clients/web/client.ts#L1266) returns the current native execution or terminal Dwell run only when the history page has not yet proven coverage; active work is not treated as missing terminal history.

[`scheduleHistoryRecovery`](../../../src/clients/web/client.ts#L1277) schedules one generation-bound retry after one second and does nothing after selection/auth/suspension changes. [`loadHistory`](../../../src/clients/web/client.ts#L1286) reads either the newest page or the `nextCursor` older page. It validates session identity, ignores stale generations, prepends unseen older entries, and merges a fresh non-pending latest page into the existing branch with `mergeHistoryEntries`. A latest response with `status: "pending"` preserves the displayed `entries`, `nextCursor`, and context snapshots; it still attaches that pending page to reducer state for coverage checks. A stale cursor resets pagination and queues a fresh latest read. A non-pending latest page also updates context snapshots and reducer coverage. If the same terminal run remains uncovered, the controller counts successful latest reads and schedules one-second retries up to three reads. After the third, it sets the saved-content failure notice only when `liveTruncated`, the history page’s `incompleteTail`, or a `projection.error` supplies evidence of possible loss; lack of coverage alone does not show the notice. Other transient failures receive one timed retry and then a user-visible retry affordance. A 401 disconnects. The `finally` path reenables pagination controls and drains one queued latest read before one older-page read.

<a id="sse-connection-selection-lifecycle"></a>
## SSE connection and selection lifecycle

[`stopStream`](../../../src/clients/web/client.ts#L1385) aborts the current fetch/read and clears its reconnect timer. [`scheduleStreamRender`](../../../src/clients/web/client.ts#L1391) coalesces bursts into one animation-frame update that refreshes navigation and conversation DOM.

[`stream`](../../../src/clients/web/client.ts#L1399) opens `/sessions/{id}/events` with the browser binding, `Accept: text/event-stream`, no-cache semantics, and the last accepted cursor when available. It validates HTTP/content type, reads the response incrementally, passes decoded text through `SSEDecoder`, rejects session-ID changes, and applies each frame with `reduceFrame`. A confirmed run change resets display order and coverage retries. Message/tool observations are added once to the bounded fallback order. Session metadata updates tabs and may trigger a model-capability probe. A matching turn request ID/session pair confirms a pending send through SSE, clearing its text and images even if the POST response was lost. Snapshot, resync, and terminal events request saved history. Stream errors enter the same catch path; non-auth failures clear the reconnect cursor and retry after two seconds, while a 401 disconnects. Reader locks are released in `finally`; aborts and stale generations exit without scheduling a retry.

[`select`](../../../src/clients/web/client.ts#L1519) is the session-transition boundary. It accepts only a target whose Pi process is not closed, saves the previous text draft, stops the prior stream, advances the selection/render generation, closes stale model UI, clears model capabilities, switches the per-session image draft, revokes saved-image URLs, clears context/live/history state, stores the selected-session preference, restores the target text draft, rerenders and resets scroll, then starts its model probe, SSE stream, and newest-history read. Late work is ignored by the new generation. [`connection`](../../../src/clients/web/client.ts#L1553) sets the connection badge text.

[`refresh`](../../../src/clients/web/client.ts#L1556) reads the authoritative session catalog and checks authentication, refresh generation, and `sessionStateGeneration` before replacing it, so it cannot overwrite a newer SSE/session mutation. It allocates slots, handles a session closed elsewhere, selects only a saved preference whose Pi process is not closed (otherwise the first such session), and requests unseen latest-turn metadata for background sessions. [`poll`](../../../src/clients/web/client.ts#L1620) prevents overlap and schedules another catalog refresh in five seconds while authenticated and active.

[`disconnect`](../../../src/clients/web/client.ts#L1642) resets browser state: it disposes image drafts, clears capability state, revokes saved-image URLs, closes image/new/model/close/host dialogs, advances auth and selection generations, stops SSE, resets recovery and polling, hides the application, and shows the pairing gate. [`connect`](../../../src/clients/web/client.ts#L1666) validates `/status`, records host mode, reveals the app, refreshes sessions, restores the selected stream if still present, and starts polling. A failed or stale authentication check returns to the pairing gate; the retry button is restored in `finally`.

<a id="sending-stopping-safe-retry"></a>
## Sending, stopping, and safe retry

[`submit`](../../../src/clients/web/client.ts#L1705) has three explicit branches. If a Pi-native extension execution is running, it aborts that exact native execution ID. Otherwise, if a Dwell turn is active, it aborts the exact turn ID. Both branches validate the response and release the send lock in `finally`. When idle, a message uses the existing `pendingSend` if one exists for this session, or captures a new UUID request ID, exact textarea text, and ordered image payload. It blocks retrying an uncertain message from another session, rejects a known text-only model with images, and ignores empty text/image submissions or intake still in progress. It rejects text over 8 KiB in UTF-8 and a command-like message whose leading whitespace is followed by `/`. The accepted body has request ID, message, and optional images.

The exact pending body stays in memory until a matching HTTP response or SSE turn acknowledgement confirms it. Success clears the text draft and attachments, refreshes the catalog, and reloads history. Most 4xx responses are definite rejection and clear the retry; 408 and transport/unknown failures preserve the same ID and bytes so retry remains the same logical request. The displayed notice says the result is unconfirmed. The host’s shared request guard remains the final validation boundary; see [turn submission](../contracts.md#turn-submission).

For example, if the host accepts a turn but the POST response is lost, the browser keeps the original request ID, text, and image payload. A matching `turn.updated` frame can confirm it and clear the draft; if no acknowledgement arrives, Retry sends that same request identity and content for the host to resolve.

<a id="directory-selection-session-creation-model-picker"></a>
## Directory selection, session creation, and model picker

[`browse`](../../../src/clients/web/client.ts#L1808) reads `/directories` with an optional encoded path and validates `isHostDirectoryListing`. Its attempt and authentication numbers ensure a response belongs to the still-open creation dialog; a pending create prevents path changes. Parent/child buttons call `browse` with host-returned paths. A truncated listing prompts the user to enter a full path because directory enumeration runs on the host. [`newSession`](../../../src/clients/web/client.ts#L2042) opens the dialog, initializes its directory from the active session, and starts that listing unless an uncertain creation already exists.

[`createSession`](../../../src/clients/web/client.ts#L2050) captures the directory and a UUID request ID into `pendingCreate`, disables edits, and posts only those two values to `/sessions`; model/thinking selection happens later. A validated success clears the pending request, closes the dialog, refreshes, and selects the created session. An uncertain failure retains the same request ID and directory so retry confirms the same creation. Definite 4xx errors and `session_start_failed` clear it. The directory input and button are restored consistently in `finally`.

[`renderModels`](../../../src/clients/web/client.ts#L1857) filters the already loaded models by provider/model text and renders selected-state, accessible button controls. [`showModels`](../../../src/clients/web/client.ts#L1885) verifies model choice is enabled, captures session/auth generations, resets capability state, opens the dialog, fetches `/models`, validates its session identity, seeds the capability cache from those model options, and renders the result only if the same session/dialog is current. [`showThinking`](../../../src/clients/web/client.ts#L1936) requests capabilities for the chosen model. If it exposes exactly one thinking level, the client applies it directly; otherwise it displays the returned levels and their current selection. Its nested button callbacks submit the captured model/level pair.

[`changeModel`](../../../src/clients/web/client.ts#L1997) ignores an unchanged choice, disables conflicting controls, and posts provider, model, and thinking level in one session update. It validates the returned session before replacing catalog state. If the response fails or is uncertain, it refreshes authoritative metadata and never replays the mutation automatically. Its `finally` path releases the model lock, updates navigation, and refreshes the picker when appropriate. Model discovery and thinking-level/image capability values come from the Pi-backed host endpoints, not a browser-maintained list.

<a id="event-bindings-page-lifecycle"></a>
## Event bindings and page lifecycle

The module binds pairing, retry, logout, host details, model picker, creation dialog, close dialog, image dialog, notice, history pagination, and sidebar controls after defining the coordinator functions. These callbacks route state changes through the helpers above. The pairing form creates and persists the random binding before `/auth/pair`; logout calls `/auth/logout` and then `disconnect`. A fine-pointer Enter key submits only when Shift and IME composition are inactive; touch keyboards keep their native Enter behavior. Clipboard image files route to `Attachments.paste`, while ordinary text remains native input. The input handler saves the selected session draft and calls the composer resizer.

[`resetCloseDialog`](../../../src/clients/web/client.ts#L2117) clears the armed tab, reviewed target, button states, and error, rerenders, and focuses the active tab or new-session control. [`dismissCloseDialog`](../../../src/clients/web/client.ts#L2130) closes and resets it. The dialog’s deferred native `close` listener checks that no newer close target replaced the one being dismissed.

[`responsive`](../../../src/clients/web/client.ts#L2251) updates drawer `inert` state when the 760 px breakpoint changes; desktop always exposes both main and rail. `pagehide` marks the browser suspended, advances the stream generation, aborts observation, and clears catalog polling. [`resume`](../../../src/clients/web/client.ts#L2273) restarts browser observation: clear stale timers, invalidate capability/model work, close the picker, release saved-image URLs, clear the old cursor, then probe the selected model, reopen the stream, reload history, poll sessions, and resize the composer. `pageshow` after back-forward-cache, `online`, and visible `visibilitychange` call this same path. Resume reconnects observation; sending the pending prompt again requires an explicit retry.

The browser-level boundary checks confirm the real shell, public browser module set, authenticated directory/model discovery, and pairing-safe routes ([`web-client.test.ts`](../../../tests/web-client.test.ts#L5), [`web.test.ts`](../../../tests/web.test.ts#L16)). Behavior-specific event, history, image, and session contracts have their own focused tests linked from the neighboring chapters and reference pages.
