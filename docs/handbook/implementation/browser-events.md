# Browser event stream and state reduction

English | [简体中文](../../i18n/zh-CN/handbook/implementation/browser-events.md)

The browser treats Server-Sent Events (SSE) as bounded observations of a host-owned Pi session. [`events.ts`](../../../src/clients/web/events.ts) converts byte-decoded text into validated protocol frames, applies frames as immutable state transitions, and joins temporary live output with paged saved history by native identity. The stream is not a transcript store: history pages remain authoritative for persisted content, while gaps and truncation are carried as explicit state. See [Browser controller](browser-controller.md) for stream reconnect, rendering cadence, and history-read scheduling.

<a id="state-bounds-protocol-errors"></a>
## State, bounds, and protocol errors

[`MAX_SSE_FRAME_BYTES`](../../../src/clients/web/events.ts#L13) caps one decoded frame at 256 KiB. The private accumulation limits bound the live view to 64 messages, 64 tools, and 64 KiB of message text plus thinking text. [`ResyncReason`](../../../src/clients/web/events.ts#L18) distinguishes stale cursors, cursors ahead of the retained stream, epoch changes, and replay-limit resync. [`ConversationState`](../../../src/clients/web/events.ts#L20) stores the active session and cursor, session/turn metadata, live message and tool arrays, live run identity, completeness/truncation flags, latest history page, resync reason, and projection/stream error. `lastCursor` preserves the most recently accepted cursor while `cursor` is cleared to request fresh synchronization.

[`SseDecodeError`](../../../src/clients/web/events.ts#L51) attaches one of six local decode codes to a human-readable error; [`SseDecodeError.constructor`](../../../src/clients/web/events.ts#L54) initializes `Error` identity and the code. [`EventFields`](../../../src/clients/web/events.ts#L61) is the parser’s current SSE block: byte count, optional event name and ID, and ordered data lines. [`emptyConversationState`](../../../src/clients/web/events.ts#L190) initializes a disconnected, empty projection, optionally scoped to a session ID. [`CursorParts`](../../../src/clients/web/events.ts#L210) is the internal parsed cursor shape: session, epoch, and safe integer sequence.

<a id="incremental-sse-decoding"></a>
## Incremental SSE decoding

[`SSEDecoder`](../../../src/clients/web/events.ts#L69) keeps partial-line and partial-event state across arbitrary network chunks. [`SSEDecoder.push`](../../../src/clients/web/events.ts#L77) ignores a single UTF-8 BOM at the beginning, recognizes LF, CR, and CRLF even when CR/LF are split across chunks, and accumulates decoded characters while counting their UTF-8 size. A surrogate pair split across JavaScript string chunks is corrected before frame-size accounting. If the line plus current block exceeds the byte cap, the decoder clears its partial parser state and throws a `frame_too_large` error; it never returns a partial protocol frame.

[`SSEDecoder.#lineEnding`](../../../src/clients/web/events.ts#L120) adds the line and terminator bytes to the current block. A blank line dispatches the event and resets its fields; comment lines (including heartbeat comments) are ignored. Other lines split at the first colon, remove one optional leading value space, and recognize only `event`, `id`, and `data`. Data lines remain in order and are joined with newlines. A NUL in an ID fails as malformed SSE.

[`SSEDecoder.#dispatch`](../../../src/clients/web/events.ts#L156) ignores blocks with no data. Otherwise it requires an event name, parses JSON, applies the shared `isStreamFrame` guard, checks that the SSE event name equals the frame’s `type`, and verifies the SSE ID matches the frame cursor (resync frames must omit the ID). It reports separate error codes for malformed fields, invalid JSON/schema, event mismatch, and cursor mismatch. [`SSEDecoder.#emptyFields`](../../../src/clients/web/events.ts#L181) starts a fresh block; [`SSEDecoder.#fail`](../../../src/clients/web/events.ts#L185) throws the typed error. [Decoder tests](../../../tests/web-events.test.ts#L205) cover fragmented CRLF, comments, multiline data, Unicode byte counts, metadata mismatches, and an oversized unfinished frame.

<a id="copying-state-joining-history-pages"></a>
## Copying state and joining history pages

The reducer avoids mutating a previously published state or a frame payload. [`copyTurn`](../../../src/clients/web/events.ts#L226) copies a turn and nested error, [`copyMessage`](../../../src/clients/web/events.ts#L231) copies a message and its blocks/ranges, [`copyTool`](../../../src/clients/web/events.ts#L246) copies a tool record, and [`copyHistory`](../../../src/clients/web/events.ts#L250) copies a history page with entry/block records. This permits consumers to retain earlier state snapshots safely.

[`cursorParts`](../../../src/clients/web/events.ts#L216) accepts only the session/epoch/sequence cursor spelling and rejects unsafe integers. [`mergeHistoryEntries`](../../../src/clients/web/events.ts#L261) combines a newly loaded latest page with an already loaded older prefix. If the new page overlaps an old entry, it keeps the prefix before that identity and replaces the rest. If it starts at the root, it replaces the old branch. Otherwise it follows the new first entry’s parent into the old page and keeps only through that parent. A parent not found in the currently loaded prefix means the pages cannot be proven to share a branch, so the incoming page replaces the old entries. An empty incoming latest page clears the list. [History merge tests](../../../tests/web-events.test.ts#L706) cover overlap, fork replacement, unrelated branches, and empty pages.

[`utf8Bytes`](../../../src/clients/web/events.ts#L277), [`isHighSurrogate`](../../../src/clients/web/events.ts#L285), and [`isLowSurrogate`](../../../src/clients/web/events.ts#L290) support byte-accurate limits even when a surrogate pair arrives across string chunks. [`isTerminal`](../../../src/clients/web/events.ts#L295) recognizes completed, failed, aborted, and interrupted Dwell turns.

<a id="saved-history-coverage-snapshot-merging"></a>
## Saved history coverage and snapshot merging

[`isTerminal`](../../../src/clients/web/events.ts#L295) recognizes the completed, failed, aborted, and interrupted Dwell turn outcomes. `coveredLiveRun` distinguishes the native-extension execution lane from a Dwell turn. A native execution is covered only after it is no longer running and the page names that native execution ID. A Dwell run is covered only when the history page names the same turn ID, no turn is active, and the latest turn for that run is terminal. [`coveredLiveRun`](../../../src/clients/web/events.ts#L304) therefore does not infer completion from matching text or from a terminal-looking event alone. [`applyCoveredHistory`](../../../src/clients/web/events.ts#L323) clears live messages and tools only after that identity-and-terminal check succeeds.

[`preserveCompatiblePrefix`](../../../src/clients/web/events.ts#L343) handles bounded snapshots: when an incoming value is explicitly truncated, it retains an older longer value only if the incoming prefix is consistent with it (with a trailing ellipsis ignored for the prefix comparison). [`mergeSnapshotMessage`](../../../src/clients/web/events.ts#L352) applies this rule to message text and thinking blocks, preserves compatible prior text ranges when the message prefix still matches, and carries forward truncation flags. [`copyMessageBlock`](../../../src/clients/web/events.ts#L379) clones one text block and its ranges or one thinking block. [`mergeSnapshotTool`](../../../src/clients/web/events.ts#L385) preserves compatible prefixes for tool name, input, and output.

[`upsertSnapshotMessage`](../../../src/clients/web/events.ts#L396) and [`upsertSnapshotTool`](../../../src/clients/web/events.ts#L412) merge a same-run snapshot item with its previous live version by ID, or add it through the bounded normal upsert path when new. Both report whether the item cap dropped older data. [`snapshotState`](../../../src/clients/web/events.ts#L425) applies a validated snapshot. It rejects an older sequence in the same session/epoch, restores the cursor if a same-sequence snapshot answers a pending resync, retains prior history only for the same session, and determines live-run identity from native execution, active turn, then latest turn. When session and run are unchanged, it merges the incoming bounded message/tool projection instead of replacing a longer compatible prefix; a changed session or run begins with fresh live arrays. The two live flags carry different evidence: `liveTruncated` preserves prior same-run truncation and records the host’s `payload.live.truncated` bit, truncated message/tool items, or client-side item drops. `liveIncomplete` preserves prior same-run incompleteness and is also set by any identified live run or visible live item, an epoch change, or an item drop; a snapshot may therefore be incomplete without being truncated. The snapshot carries only the current live projection, not a complete run transcript. It then returns the snapshot’s session, turn metadata, cursor, and cleared prior error/resync reason.

<a id="live-delta-accumulation"></a>
## Live delta accumulation

[`upsertMessage`](../../../src/clients/web/events.ts#L522) replaces an existing message by ID or appends a defensive copy, keeping only the newest 64; adding a 65th drops the oldest and reports that loss. [`appendDelta`](../../../src/clients/web/events.ts#L542) ignores deltas for finished messages, computes remaining UTF-8 budget across visible text and thinking blocks, and appends only complete characters that fit the 64 KiB per-message cap. For user-visible text blocks it records content-index ranges into the combined message text; adjacent ranges coalesce and at most 64 disjoint ranges are retained. If another disjoint range would exceed that cap, the fitting suffix still enters `message.text`, but the block is marked truncated and no range is added for that span, so the range-based renderer cannot display it. The block itself is not dropped. Thinking deltas accumulate in their own indexed block and do not enter the visible text string. Blocks remain ordered by native `contentIndex`. UTF-8 clipping and range loss mark the message/block as truncated and the live projection as incomplete. [`messageThinkingBytes`](../../../src/clients/web/events.ts#L637) counts thinking-block bytes as part of that same message budget. [`upsertTool`](../../../src/clients/web/events.ts#L645) performs the equivalent by-ID replacement/append for tools while retaining the newest 64; adding beyond the cap drops the oldest tool and reports the loss. Reducer state surfaces dropped message/tool items as both truncation and incompleteness.

<a id="event-reducer-branches-cursor-rules"></a>
## Event reducer branches and cursor rules

[`reduceFrame`](../../../src/clients/web/events.ts#L664) rechecks `isStreamFrame` at the state boundary and ignores a frame for a different already-selected session. A `resync` clears only the request cursor while remembering the last accepted cursor and reason; live content remains visible but is marked incomplete. A `snapshot` delegates to `snapshotState`. Other frames require a parseable cursor in the same session and epoch as the prior cursor. Duplicate/older sequences are ignored; a skipped sequence marks the live projection incomplete. With no previous cursor, any sequence after the first also signals a gap.

The frame switch then updates only the state named by the event. `session.updated` replaces session metadata and can identify a native execution; a changed run clears its old message/tool projection. `turn.updated` updates active/latest turn metadata, clears a prior run’s live items when the run ID changes, and considers only nonterminal statuses active. Message start/finish frames upsert the full message; deltas append bounded content. Tool start/update/finish frames upsert tool state. A message/tool frame is rejected for run mismatch only when both the current `liveRunId` and incoming `frame.runId` are non-null and differ. If the state has no run ID, a tagged frame adopts its incoming ID; an untagged frame does not assign one. `projection.limited` marks metadata or live content truncated according to its scope. `projection.error` and `stream.error` are retained as typed state errors. After session/turn events, `applyCoveredHistory` may clear only a saved-and-terminal run.

[`reconcileHistory`](../../../src/clients/web/events.ts#L814) validates a history page and requires it to match the current session before attaching a defensive copy and applying coverage. [`visibleLiveContent`](../../../src/clients/web/events.ts#L822) removes only live messages with a `nativeKey` already present in saved entries and live tools with a matching native owner/call pair. It then combines messages and tools by their observation order. Repeated display text remains distinct when native identities differ. Once saved native content proves an item is persisted, the saved renderer displays it; remaining live items stay visible until the whole run is covered. [Reducer tests](../../../tests/web-events.test.ts#L330) cover frame accumulation, order, immutability, gaps/resync, bounds, native identity handoff, and separate native execution coverage.
