# Browser input and attachments

English | [简体中文](../../i18n/zh-CN/handbook/implementation/browser-input.md)

This chapter covers page-local image drafts and input handling: per-session asynchronous file intake, textarea and viewport sizing, scroll anchoring, and guarded long-press Backspace. `Attachments` keeps image bytes and preview object URLs in the current browser page. Submitted image content travels with a turn request, and Pi’s native history holds the saved record. See [Browser controller](browser-controller.md) for send and model-capability decisions and [Browser rendering](browser-rendering.md) for the composer shell and displayed saved images.

<a id="attachment-ownership-callbacks"></a>
## Attachment ownership and callbacks

[`Attachment`](../../../src/clients/web/attachments.ts#L11) holds one local draft’s generated ID, display name, object URL, and JSON-safe `ImageContent`. [`Attachments`](../../../src/clients/web/attachments.ts#L17) owns a map of these arrays keyed by session ID, plus a pending-session set, selected session, two disabled flags, and a generation counter. Its DOM references are the hidden file input, visible tray and button. The `change` callback refreshes controller enabled state, `error` reports failed intake, and `preview` opens the selected draft image. The [`Attachments.constructor`](../../../src/clients/web/attachments.ts#L30) binds the button to the input picker and the input’s change event to `add`; it clears the native input value immediately so choosing the same file again can still emit a change.

[`Attachments.select`](../../../src/clients/web/attachments.ts#L50) changes which session’s drafts are visible without moving or deleting another session’s files. [`Attachments.setDisabled`](../../../src/clients/web/attachments.ts#L54) separates general sending/interaction disablement from intake disablement: the add button follows the latter, while each remove button follows the former. This allows a user to remove a now-incompatible image even when the selected model cannot accept new images. [`Attachments.busy`](../../../src/clients/web/attachments.ts#L61) reports pending intake for the selected session, and [`Attachments.count`](../../../src/clients/web/attachments.ts#L64) reports that session’s draft count. [`Attachments.payload`](../../../src/clients/web/attachments.ts#L67) returns the current session’s ordered image records without preview URLs.

[`Attachments.clear`](../../../src/clients/web/attachments.ts#L70) revokes every draft URL for one session and deletes its draft list; it rerenders only when that session is currently selected. [`Attachments.dispose`](../../../src/clients/web/attachments.ts#L75) increments the generation to invalidate outstanding decodes, clears pending markers, revokes all draft URLs, clears all sessions, and removes the selected session. It is the authentication-loss cleanup path in the client. [`Attachments.paste`](../../../src/clients/web/attachments.ts#L82) reads files from clipboard data; if there are files, it prevents the browser’s default paste behavior and routes intake through `add` only when image intake is enabled. Plain-text paste remains the composer’s normal browser behavior.

<a id="file-intake-preview-rendering"></a>
## File intake and preview rendering

[`Attachments.add`](../../../src/clients/web/attachments.ts#L88) captures the current session and generation, then exits if there is no session, intake is disabled, or that session already has an intake in progress. Its per-file loop enforces the shared maximum image count and aggregate decoded image-byte limit, then allows PNG, JPEG, WebP, and GIF MIME types. It reads the file as a data URL, extracts the base64 payload, and validates the result with the shared `isImageContent` guard, which checks supported MIME, data encoding, image signature, and size. It creates a temporary object URL and asks the browser to decode the image before exposing it in the tray. The whole loop sits inside one outer `try/catch`: the first validation, read, or decode failure stops the remaining batch files and calls `error` once; items added earlier in the batch remain in the session draft.

After each asynchronous read/decode, `add` rechecks that its generation and session are still current and that intake is still enabled. A stale or newly disabled result is revoked and discarded. For clipboard files with generic browser names, the display name becomes “Pasted image”; otherwise it preserves the file name, falling back to “Image”. A successful item gets a random ID, is appended to the session draft list, and triggers a tray render. Failures are passed to the caller’s `error` callback only while the generation remains current. The `finally` path removes the pending marker and signals `change` only for the generation that owns it, so disposal cannot let a late decode mutate current UI state.

The private [`Attachments.#render`](../../../src/clients/web/attachments.ts#L154) rebuilds the selected session’s tray with text-backed buttons. Repeated generic clipboard images get numbered labels. Preview buttons call the supplied preview callback with the current object URL and label. Remove buttons are disabled during general sending work; activation filters the item by its generated ID, revokes its URL, rerenders, and notifies the controller. The image bytes remain in the draft payload until a successful turn or explicit clearing; there is no upload request while a draft is being edited.

The controller constructs `Attachments` with `change: () => navigation()`, `error: showError`, and `preview: showImage` in [`client.ts`](../../../src/clients/web/client.ts#L191). It derives intake enablement from authentication, whether the Pi process is ready, active work, model capability checks, and the current model’s `supportsImages` result. An unknown or failed image capability check blocks new intake; an existing item remains removable. Before submission, the controller checks image support again if a negative result is known. The browser’s image picker uses the shell’s fixed accept list in [`page.ts`](../../../src/clients/web/page.ts#L73).

<a id="composer-sizing-and-viewport-adaptation"></a>
## Composer sizing and viewport adaptation

[`BackspaceHold`](../../../src/clients/web/input.ts#L3) stores the trusted key-hold start time, last repeat time, and expected caret. The module uses [`MAX_HEIGHT_PX`](../../../src/clients/web/input.ts#L9), [`MIN_HEIGHT_PX`](../../../src/clients/web/input.ts#L10), and [`VIEWPORT_HEIGHT_RATIO`](../../../src/clients/web/input.ts#L11) to keep a growing textarea within a viewport-relative bound. [`setupComposer`](../../../src/clients/web/input.ts#L13) records the original rows, inline sizing, body viewport styles, scroll height, and bottom gap before registering listeners. It returns an explicit `resize()` and `dispose()` interface; the client calls `resize()` after text/session changes.

The nested [`setupComposer.restoreBodyViewport`](../../../src/clients/web/input.ts#L36) restores the exact initial inline body height and top offset. [`setupComposer.rememberScrollPosition`](../../../src/clients/web/input.ts#L41) records the reader’s distance from the bottom only when the scroll container’s client height has not already changed; this avoids replacing the last valid anchor with a transient keyboard-resized measurement. [`setupComposer.resize`](../../../src/clients/web/input.ts#L48) first retains that bottom gap, then on mobile checks whether the native `interactive-widget=resizes-content` behavior kept the document inside `VisualViewport`. It skips the fallback during pinch zoom. If the active textarea still lies outside the visual viewport, it temporarily pins the body to the visual viewport’s height and top offset; otherwise it restores the native layout. It collapses the textarea to measure content, caps its height at the smaller of a viewport share and a device-specific maximum (with a small mobile minimum), switches to internal scrolling when needed, and restores the conversation’s prior bottom gap. A reader following the latest output stays at the bottom; a reader browsing older messages keeps the same lower-edge offset.

The nested [`setupComposer.viewportChanged`](../../../src/clients/web/input.ts#L100) batches repeated window/visual viewport changes into one animation frame. A `ResizeObserver` watches the composer form and reruns sizing only when its width changes. `resize` checks a disposed flag, so callbacks already queued during teardown become harmless. The shell’s viewport metadata requests the native keyboard-resizing behavior, with this fallback reserved for browsers whose visual viewport changes while the layout viewport remains obscured.

<a id="trusted-long-press-backspace"></a>
## Trusted long-press Backspace

The nested [`setupComposer.onInput`](../../../src/clients/web/input.ts#L112) always resizes. It ignores edits performed by the custom repeat loop and tracks the resulting caret; normal input resets the hold unless the event is a non-composing native backward deletion with a collapsed selection. [`setupComposer.supportsNativeDelete`](../../../src/clients/web/input.ts#L136) feature-detects `document.execCommand("delete")` behind a guarded compatibility check. If the API is absent or throws, accelerated deletion is disabled and the browser keeps its native repeat behavior.

The nested [`setupComposer.onKeyDown`](../../../src/clients/web/input.ts#L148) accelerates only trusted, non-prevented Backspace events with no modifier, active composition, read-only/disabled state, or selection. A fresh non-repeat event establishes a hold. Repeats stop accelerating if more than one second elapsed between repeats or if the caret no longer matches. The deletion step stays at one character for the first 1.2 seconds, then grows to two, four, and eight characters at 2.4 and 4 seconds. It does nothing at the start of the text and uses the browser’s native deletion command so the edit participates in normal input/undo behavior. If native input events were not emitted, it dispatches one synthetic bubbling `input` event; if no text changed or execution failed, it clears the hold.

The handlers named inside `setupComposer` each reset or maintain that hold for a distinct browser signal: [`setupComposer.resetBackspace`](../../../src/clients/web/input.ts#L108) clears it; [`setupComposer.onCompositionStart`](../../../src/clients/web/input.ts#L220) and [`setupComposer.onCompositionEnd`](../../../src/clients/web/input.ts#L225) mark IME composition and clear it; [`setupComposer.onSelectionChange`](../../../src/clients/web/input.ts#L230) cancels when the caret or selection moves; and [`setupComposer.onSelect`](../../../src/clients/web/input.ts#L239) cancels for a non-collapsed selection. A keyup, pointerdown, input blur, document/window blur, visibility change, or disposal also prevents a stale hold from continuing after focus changes. The setup installs these listeners once and sizes the initial composer immediately.

<a id="cleanup-current-test-boundary"></a>
## Cleanup and tests

The returned [`setupComposer.dispose`](../../../src/clients/web/input.ts#L277) callback marks the setup disposed, resets the hold, disconnects the observer, removes every registered listener, cancels any pending viewport frame, and restores the original body and textarea inline styles. During a back-forward-cache `pagehide`/`pageshow` cycle, the composer setup remains attached while the client suspends and resumes network observation. Browser shell and asset exposure are checked in [web tests](../../../tests/web.test.ts#L6); shared image payload constraints are checked in [image tests](../../../tests/images.test.ts#L100).
