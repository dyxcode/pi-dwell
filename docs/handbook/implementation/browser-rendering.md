# Browser rendering internals

English | [简体中文](../../i18n/zh-CN/handbook/implementation/browser-rendering.md)

This chapter follows the browser’s output path: the HTML shell, the fixed browser module set, safe Markdown conversion, saved and live conversation projection, and DOM updates. The controller and network lifecycle are described in [Browser controller](browser-controller.md); stream framing and reduction are in [Browser events](browser-events.md). These modules render host-provided projections. They do not execute Pi or decide which transcript branch is authoritative.

<a id="page-shell-styles-browser-assets"></a>
## Page shell, styles, and browser assets

[`HOST_PAGE`](../../../src/clients/web/page.ts#L1) is the English HTML shell returned by the host. Its landmarks divide into the pairing gate, hidden application shell, navigation and open-session status strip, conversation/history region, composer, and native dialogs for closing a session, creating one, choosing a model, viewing host details, and previewing an image. The stable element IDs form the startup contract with `client.ts`: its `el()` helper checks that each required element exists and has the expected DOM class before listeners are attached. Semantic labels, live status regions, keyboard focus targets, a constrained eight-character pairing pattern, external same-origin script and stylesheet references, and native `dialog` elements are part of the shell, not generated by the renderer.

[`STYLE`](../../../src/clients/web/page.ts#L138) is served from the same module as the HTML. Its variables define the paper/surface palette, type stacks, and state colors; its layout rules establish the two-column desktop shell, bounded conversation width, message spacing, composer, disclosure rows, and dialog surfaces. Later rule groups tune conversation groups, tool and thinking disclosures, image chips, session status tabs, recovery messages, and command previews. At 760 px and below, the sidebar becomes an inert-unless-open drawer, dialogs become bottom sheets, and the conversation/composer spacing contracts for touch. Very narrow and short viewports receive additional constraints. Focus-visible outlines, hidden-screen-reader labels, safe-area padding, `dvh`, and reduced-motion handling support keyboard and mobile use. `page.ts` has data constants rather than callable declarations; its CSS class contract is consumed by the controller and renderers.

[`modules`](../../../src/clients/web/script.ts#L6) is a fixed map from public browser URLs to repository TypeScript modules. It includes the client, browser helpers, and their shared protocol modules; request paths never select filesystem locations. [`BROWSER_ASSETS`](../../../src/clients/web/script.ts#L26) reads only those entries, strips TypeScript syntax using Node’s native stripper, rewrites relative `.ts` imports to `.js`, and maps the pinned `marked` import to `/vendor/marked.js`. It adds the exact installed `marked` module at that vendor path. [`BROWSER_SCRIPT`](../../../src/clients/web/script.ts#L38) is the `/client.js` entry text. In the HTTP GET handler, [`http.ts`](../../../src/server/http.ts#L477) returns `HOST_PAGE` as HTML for `/`, the matching allowlisted JavaScript for a known asset path, and `STYLE` as CSS for `/style.css`; other paths continue through authentication. [Browser asset tests](../../../tests/web.test.ts#L6) check same-origin loading, compiled import shape, module membership, and exclusion of server authentication code.

<a id="dom-identity-reconciliation"></a>
## DOM identity and reconciliation

Each render builds a desired `DocumentFragment`, while the existing conversation may contain nodes with focus, open `<details>`, image callbacks, or preserved previews. [`elementIdentity`](../../../src/clients/web/dom.ts#L3) chooses the first present identity attribute in priority order: `data-key`, `data-entry-id`, then `data-session-id`, with namespace and local tag name included. [`compatible`](../../../src/clients/web/dom.ts#L12) permits reuse only for nodes of the same node kind and, for elements, the same namespace and tag. [`synchronizeAttributes`](../../../src/clients/web/dom.ts#L19) removes stale attributes and copies changed desired attributes. [`hasSamePreserveMarker`](../../../src/clients/web/dom.ts#L29) recognizes an explicit `data-preserve` marker shared by both versions.

[`reconcileElement`](../../../src/clients/web/dom.ts#L35) updates a compatible element in place. It preserves a subtree when its identity and render version match, or when its preserve marker matches; otherwise it reconciles children. It replaces the element’s `onclick` property with the newly rendered handler and retains an already-open disclosure (`<details>`) when a compatible replacement is still present. [`reconcileChildren`](../../../src/clients/web/dom.ts#L56) first indexes existing keyed elements, then matches keyed desired nodes by identity and unkeyed nodes by compatible type in forward order. If preserve markers differ, the old node is discarded rather than reused. It moves or inserts desired nodes into order and removes old nodes that were not retained. This gives the renderers a fresh-tree interface while keeping stable interactive nodes alive.

Matching node identity and `data-render-version` skip child traversal, while attributes and parent position are still reconciled. A changed version permits child updates. A matching preserve marker leaves the current element and descendants untouched, which the controller uses while an asynchronous saved-image request is upgrading its placeholder. Conversation rendering supplies stable `data-key` values for live and saved groups; detailed message-to-DOM rules are below.

<a id="markdown-explicit-dom"></a>
## Markdown becomes explicit DOM

[`record`](../../../src/clients/web/markdown.ts#L4) accepts only non-null, non-array objects and returns a plain record for token inspection; [`text`](../../../src/clients/web/markdown.ts#L9) narrows unknown values to strings. [`entities`](../../../src/clients/web/markdown.ts#L12) decodes a small named-entity set and numeric code points, replacing invalid Unicode scalar values with the replacement character. It does not treat decoded content as markup. [`safeLink`](../../../src/clients/web/markdown.ts#L33) resolves a target against the current page and accepts only `http:`, `https:`, and `mailto:` schemes. An invalid or unsupported target still renders as text inside an anchor-shaped node without an `href`.

[`renderMarkdown`](../../../src/clients/web/markdown.ts#L42) asks `marked.lexer` for GFM tokens, then recursively turns the supported token structure into DOM nodes. Its nested [`renderMarkdown.append`](../../../src/clients/web/markdown.ts#L45) caps traversal at depth 64 and 12,000 visited tokens. The renderer skips non-display tokens, constructs code figures and optional language labels, scrollable tables, ordered/unordered lists and disabled task checkboxes, links, headings, paragraphs, emphasis, quotes, breaks, and rules. The nested [`renderMarkdown.append.row`](../../../src/clients/web/markdown.ts#L77) builds table cells and applies only the three recognized alignments. Text is assigned with `textContent` or `createTextNode`; raw HTML tokens are displayed as text. No token string is assigned to `innerHTML`. A Markdown image token does not load an `<img>`: it creates an anchor with the alt text (or “Image”) as its label. If `safeLink` accepts the target, that anchor is a clickable link opened in a new tab with `noopener noreferrer`; an invalid or unsupported target leaves the anchor without `href`. Saved transcript images use the separate authenticated image renderer. Unknown token types descend into child tokens when available, otherwise they become text.

<a id="saved-grouping-tool-pairing"></a>
## Saved grouping and tool pairing

[`groupConversationEntries`](../../../src/clients/web/conversation.ts#L14) maps the ordered history page into alternating user groups and assistant response groups. Its nested [`groupConversationEntries.flushResponse`](../../../src/clients/web/conversation.ts#L19) closes the current response immediately before a user entry and once at end-of-page. Every non-user role stays in the response group, including assistant messages, tool results, bash records, context, diagnostics, and extension messages; a tool or context record does not create a false user boundary.

[`pairToolResults`](../../../src/clients/web/conversation.ts#L44) first queues saved `toolResult` entries by `toolCallId`, then walks tool-call blocks in entry/block order and consumes one queued result per call. It returns a lookup keyed by saved entry ID plus block index, the matched result IDs, and unmatched result entries. Queue offsets preserve repeated call IDs without attaching one result to multiple calls. An orphan result remains visible as its own disclosure instead of disappearing. The behavior is exercised by [conversation tests](../../../tests/conversation.test.ts#L91).

The small DOM helpers keep construction consistent: [`node`](../../../src/clients/web/conversation.ts#L84) creates an element and uses `textContent`; [`keyed`](../../../src/clients/web/conversation.ts#L95) adds the reconciliation key and optional saved-entry identity; [`markdown`](../../../src/clients/web/conversation.ts#L101) skips empty text and delegates non-empty text to the safe renderer. [`appendImage`](../../../src/clients/web/conversation.ts#L105) asks its callback for an entry/index-scoped image node, adds the source identity attributes, and degrades to “Saved image unavailable” if metadata is incomplete or the callback fails. [`appendMarkdownBlocks`](../../../src/clients/web/conversation.ts#L125) preserves block order while leaving thinking and tool-call blocks for their specialized renderers.

<a id="message-thinking-context-rendering"></a>
## Message, thinking, and context rendering

[`thinkingPresentation`](../../../src/clients/web/conversation.ts#L137) uses a short first-line Markdown heading or bold line as a disclosure title and removes that heading from the body. Empty, inline-only, plain, or over-72-UTF-16-code-unit headings retain the generic “Thinking” title and the full source. [`thinkingDisclosureKey`](../../../src/clients/web/conversation.ts#L145) keys a disclosure by native message identity and content index, allowing live output to hand off to saved history without losing its open state. [`thinkingDisclosure`](../../../src/clients/web/conversation.ts#L149) creates a closed-by-default `<details>` element whose body goes through `renderMarkdown`.

[`renderLiveMessageBlock`](../../../src/clients/web/conversation.ts#L164) has two branches. Thinking blocks become keyed disclosures carrying message and content-index metadata. Text blocks rebuild their visible string from valid, ordered ranges into the message’s accumulated text, and return `null` for an empty result. Those ranges let the UI display interleaved thinking and user-facing text in native content order without revealing thinking as response text. [`thinkingDetails`](../../../src/clients/web/conversation.ts#L193) gives a saved thinking block the same identity rule. [`appendTruncated`](../../../src/clients/web/conversation.ts#L309) adds a short footnote when a saved entry is shortened by the history projection.

[`renderUser`](../../../src/clients/web/conversation.ts#L314) creates one article per user entry, marks a scroll anchor, renders text/image blocks, and adds any truncation notice. [`renderAssistant`](../../../src/clients/web/conversation.ts#L326) creates one article for the entire response group. It skips matched result entries because their content is shown under the originating tool call; keeps anchors for each saved entry; routes extension/custom, context, diagnostic, and `role: null` entries through `renderSpecial`; shows unmatched tool results as orphan disclosures; formats bash execution records as shell disclosures; and walks ordinary assistant blocks in order. `role: null` is treated as diagnostic and becomes a collapsed “Saved history note” disclosure. Tool-call disclosures receive any currently observed live tool with the same native owner/call identity, so an incomplete saved result can still display its running state. Images use the caller’s scoped image renderer and text uses safe Markdown.

[`renderSpecial`](../../../src/clients/web/conversation.ts#L410) presents custom extension output as an ordinary labeled message. Context, diagnostic, and `role: null` entries use collapsed disclosures with role-appropriate labels; a null role is classified as diagnostic and titled “Saved history note.” [`renderContext`](../../../src/clients/web/conversation.ts#L438) creates a session-context disclosure only when there are sources or a truncation notice. Each instruction source is individually keyed by path, labeled with truncation status, and rendered as Markdown; the caption explains that the content is the instruction snapshot saved in Pi. [`renderSavedConversation`](../../../src/clients/web/conversation.ts#L478) provides stateless composition of the saved view: prepend context when present, group the entries, render user and assistant groups, and return a fragment. Its default image callback displays a placeholder; the application supplies the authenticated loader.

<a id="tool-disclosures-command-summaries"></a>
## Tool disclosures and command summaries

[`appendRawOutput`](../../../src/clients/web/conversation.ts#L205) skips thinking/tool-call blocks, shows saved images through the image callback, and emits text as `<pre>` content; an empty non-image result gets an explicit “No output saved” row. [`bashCommand`](../../../src/clients/web/conversation.ts#L226) parses only an object with a string `command` field and only when the saved tool name is `bash`; malformed input falls back to generic tool rendering.

[`toolRun`](../../../src/clients/web/conversation.ts#L244) builds a keyed disclosure for a saved call/result, a live tool, a shell command, or an orphan result. Errors open by default. Shell summaries use [`appendToolCommand`](../../../src/clients/web/tool-command.ts#L28); other tools show their name. The status distinguishes error, completed, running, saved shell output, unmatched result, and missing saved result. The body shows structured tool input, saved or live output, saved images, and truncation notes according to which record is available. A shell execution’s output blocks are taken from its owner record with the call block removed, because that projection stores call and output together.

[`ActionIcon`](../../../src/clients/web/icons.ts#L3) is the closed set of supported control symbols. [`actionIcon`](../../../src/clients/web/icons.ts#L5) creates a small inline SVG from a fixed path table, marks it decorative with `aria-hidden`, and uses current text color for the stroke; it introduces no image request or icon font. [`labelWithIcon`](../../../src/clients/web/icons.ts#L31) builds a text span plus that SVG, applies the shared button class, and replaces the button’s children with either icon-leading or icon-trailing order. The visible text remains the accessible label; callers provide button-specific `aria-label` where the action name needs more context.

[`commandLines`](../../../src/clients/web/tool-command.ts#L9) splits CRLF, CR, or LF and drops one final empty segment caused by a trailing newline. [`commandPresentation`](../../../src/clients/web/tool-command.ts#L15) summarizes multiline input using its first nonblank trimmed line, counts physical lines, and prefixes the preview with `$`; a single-line command preserves its exact content. [`appendToolCommand`](../../../src/clients/web/tool-command.ts#L28) appends the preview as text and, for multiline commands, adds a line count and returns a separate full-command `<pre>` for the caller to place in the disclosure. The collapsed row shows the summary and line count; expanding the disclosure shows every command line. [Conversation tests](../../../tests/conversation.test.ts#L12) cover line endings, blank lines, heading fallback, and stable thinking keys.

<a id="saved-group-rendering-cache"></a>
## Saved-group rendering cache

[`SavedConversationRenderer.clear`](../../../src/clients/web/conversation.ts#L511) invalidates the cached entries, group signatures, and keyed shells. [`SavedConversationRenderer.render`](../../../src/clients/web/conversation.ts#L517) recomputes groups only when the entries array identity changes, records JSON signatures and native owners for each group, and separately signs context sources. Its nested [`SavedConversationRenderer.render.append`](../../../src/clients/web/conversation.ts#L537) helper reuses an unchanged shallow shell for the caller’s DOM reconciler to retain the existing subtree. A changed group is fully rendered and tagged with a new render version. Live tools owned by a saved group are included in that group’s signature, so a running/completed status update refreshes the affected group while unrelated saved groups remain untouched. Removed keys leave the cache. The cache preserves completed Markdown DOM and image callbacks across streaming frames; `reconcileChildren` then preserves their keyed nodes, focus, and disclosure state.
