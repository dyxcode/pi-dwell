# Session service

English | [简体中文](../../i18n/zh-CN/handbook/implementation/sessions.md)

[Implementation index](README.md) · [Session overview](../sessions-storage.md) · [System flow](../system.md)

`SessionService` coordinates durable Dwell sessions and turns with one Pi process per open Dwell session. It starts and observes Pi sessions, reads their saved JSONL history, tracks extension-started native executions, and publishes session events.

<a id="session-identity-and-recovery"></a>

## Identity, startup, and recovery

[`SessionError`](../../../src/sessions/service.ts#L55) carries an HTTP status and stable code with its message. [`SessionService.constructor`, `SessionService.create`, and `SessionService.runtimeCount`](../../../src/sessions/service.ts#L231) establish the service. `create` prepares the private data directory, opens `SessionCatalog`, validates stored sessions and turns before recovery, marks leftover `creating` sessions and nonterminal turns interrupted, and closes the catalog before rethrowing a validation or reconciliation failure. `runtimeCount` counts live Pi child-process objects, not catalog rows.

The module-level helpers provide the identity and view rules used by that lifecycle:

| Declaration | Behavior |
| --- | --- |
| [`turnPayloadIdentity`](../../../src/sessions/service.ts#L81) | SHA-256 of message text when there are no images; otherwise hashes a versioned object containing the text and image type, MIME type, and data in order. It distinguishes same-key retries with different attachment payloads. |
| [`validateStored`](../../../src/sessions/service.ts#L93) | Rejects invalid Dwell/request/Pi session IDs and non-absolute stored directory or session-file paths as catalog corruption. |
| [`isMessageAfterBaseline`](../../../src/sessions/service.ts#L147) | Parses `digest:occurrence` and accepts only a lowercase SHA-256 digest with a safe occurrence strictly greater than the stored count. |
| [`messageKeysAfterBaseline`](../../../src/sessions/service.ts#L159) | Computes saved assistant-message identities newer than a baseline. It returns `undefined` above 1,024 identities so later coverage checks fail closed. |
| [`messageKeyDelta`](../../../src/sessions/service.ts#L169) | Expands digest-count differences into occurrence keys; a regressed count or a result above 1,024 returns `undefined` rather than guessing. |
| [`turnView`](../../../src/sessions/service.ts#L183) | Removes the private payload digest before a stored turn is exposed as `TurnInfo`. |
| [`active`](../../../src/sessions/service.ts#L188) | Defines `accepted`, `dispatching`, and `running` as nonterminal turn statuses. |
| [`truncateUtf8`](../../../src/sessions/service.ts#L192) | Truncates by Unicode code point while enforcing a UTF-8 byte ceiling, used for native execution error text. |

`SessionService.constructor` snapshots the supplied environment (or host environment), extension paths, clock, and internal checkpoint callback. Its maps track PiProcess instances, observers, history identity baselines, native executions, coalesced native-state refreshes, active turns, and storage-faulted sessions; the catalog holds durable state while these maps hold live process coordination. [`configure`](../../../src/sessions/service.ts#L259) is serialized with other mutations, refuses changes while a Pi process or Dwell turn exists, verifies the absolute Pi configuration, normalizes verification failures to `invalid_runtime`, and saves the verified paths.

[`#configuration`, `#admit`, `#mutate`, and `#read`](../../../src/sessions/service.ts#L1446) define configuration lookup, admission and concurrency. `#configuration` returns the saved executable/entry-point pair or throws `runtime_unavailable` when it is absent. `#admit` rejects new operations once shutdown starts. `#mutate` chains mutations through one promise queue and resets the tail after success or failure, so one rejected operation does not block later work. `#read` admits at most two service-level history/result reads, tracks them for shutdown, maps `HistoryReadError` to `SessionError`, translates shutdown-triggered `AbortError`, and releases its read slot in `finally`. The lower-level Pi session-file scanner has a separate Dwell host-process budget of two active scans and eight waiters; see [History](history.md#history-scan-budget).

<a id="sessions-discovery-and-observation"></a>

## Directory and model discovery; event subscription

[`listSessions` and `getSession`](../../../src/sessions/service.ts#L282) synchronously admit a read and map catalog rows through `#view`. [`listDirectories`](../../../src/sessions/service.ts#L292) defaults an omitted path to the host home directory (`HOME`, or `USERPROFILE` on Windows); if no home is available it returns `home_directory_unavailable`. Discovery errors retain their public status/code, while unrelated filesystem errors propagate.

[`listAvailableModels`](../../../src/sessions/service.ts#L315) requires saved Pi executable configuration and coalesces global discovery into one in-flight promise, clearing it on either outcome. [`listSessionModels`](../../../src/sessions/service.ts#L340) requires a stored, non-faulted session with a ready or running Pi process. It coalesces reads by process object and confirms that the same process remains open before returning; Pi or parsing failures become `model_discovery_failed`. [`getSessionModelCapabilities`](../../../src/sessions/service.ts#L383) validates a provider/model request, requires an exact match in the active Pi session's registry, and returns provider, model ID, image support, and thinking levels. [`getModelCapabilities`](../../../src/sessions/service.ts#L403) uses isolated global discovery, coalesces identical provider/model pairs, and allows at most two distinct checks; further checks return `model_discovery_busy`.

[`subscribeEvents`](../../../src/sessions/service.ts#L442) builds a current session view and current/latest turn projections from durable state before asking `SessionEvents.connect` to register a listener. It translates malformed cursor, per-session/global subscriber overflow, and stream-capacity errors into `invalid_cursor`, `subscriber_limit`, and `stream_unavailable`. [`#publishState`](../../../src/sessions/service.ts#L473) publishes a session-only or session-plus-turn view. Because publication is observation after state mutation, a projection failure is converted to a bounded `state_unavailable` stream error instead of undoing the saved mutation. [`#storageFault`](../../../src/sessions/service.ts#L496) marks a session once in process memory and sends `storage_unavailable` to its stream; later durable turn operations reject until the host is restarted after repair.

<a id="sessions-create-open-close"></a>

## Create, open, close, and select a model

[`createSession`](../../../src/sessions/service.ts#L506) runs inside the mutation queue. It validates a request UUID, absolute directory, and all-or-none provider/model pair before hashing the original request payload. It looks up the request key before touching the directory, so a retry can resolve after the original directory disappears; changed content under the same key returns `request_conflict`. For a new key it verifies configuration, canonicalizes the directory with `#directory`, prunes exited children, enforces the eight-open-Pi-process limit, inserts a `creating` row, and then starts Pi. A successful start returns `ready`; a startup exception is recorded as `failed` and returned as a session view. The durable pre-start insert lets recovery distinguish abandoned creation from a missing record.

[`openSession`](../../../src/sessions/service.ts#L694) serializes a call to `#open`. `#open` reuses a ready Pi process and rejects a running one, prunes dead children, checks process capacity/configuration, and confirms the saved project directory still resolves to its canonical path. If an expected Pi session file is missing, it records `history_unavailable` and refuses to create a replacement Pi session. Otherwise it captures a complete history-identity baseline, starts Pi with the validated Pi session file or stored Pi session ID, and supplies a saved provider/model only for a new Pi session. It verifies the returned Pi session ID, selected model, and session file. When resuming, Pi's saved model and thinking state are authoritative; a new Pi session may receive the stored thinking level if no native execution is already active. Only then does the service save `ready` metadata. A post-start mismatch or catalog-write failure stops the Pi process, unregisters observers, and removes it from the process map.

[`setSessionModel`](../../../src/sessions/service.ts#L587) accepts a valid request only for a ready, idle Dwell session. An already-selected provider/model pair is a no-op unless a different thinking level was supplied. It opens or reuses the Pi process, checks the prior state, sends `set_model` only when needed, optionally sets thinking, and reads Pi state back to confirm the session and model. It saves the confirmed provider/model/thinking values before returning. A known rejection for an unavailable model or missing API key becomes `model_unavailable`; other unconfirmed results stop the Pi process and return `model_change_failed`. If saving fails after Pi changes the model, the service also stops that process.

[`closeSession`](../../../src/sessions/service.ts#L698) refuses an active Dwell turn or Pi run. Before stopping the Pi process, it remembers the current Pi session-file pointer and history-expectation state; a settled native execution with a baseline also gets a history-coverage refresh. It then stops the process, detaches listeners, removes the process mapping, and returns the durable session view. [`getContext`](../../../src/sessions/service.ts#L729) opens the Dwell session, requests Pi's current model-context messages, refreshes saved-history metadata, and returns them. These messages are Pi's working context; `getHistory` reads the saved Pi-session branch.

[`#directory`](../../../src/sessions/service.ts#L1553) requires an absolute, existing directory and returns its `realpath`; failures and non-directories become `invalid_directory`. [`#prune`](../../../src/sessions/service.ts#L1569) stops and releases failed/exited Pi processes, detaches their observers, and publishes the changed view before another process consumes capacity. [`#view`](../../../src/sessions/service.ts#L1514) validates its stored input and maps durable Dwell-session state plus Pi-process state to public `SessionInfo`: process `starting`/`stopping` become API `runtimeState` `opening`/`closing`; process `ready`/`running` become `ready`; `failed` remains `failed`; and an absent/exited process becomes `closed`. It derives history state from the durable expectation/error, masks storage-fault details with a stable repair message, and adds native execution and active/latest turn IDs. [`#stored`](../../../src/sessions/service.ts#L1506) validates the Dwell session ID, existence, and stored identity; [`#storedTurn`](../../../src/sessions/service.ts#L1093) checks a run ID and its owning session.

[`#rememberHistory`](../../../src/sessions/service.ts#L2020) skips failed/exited Pi processes, reads current Pi state, combines the session-file path with the latest catalog record, and asks `#history` to validate the file. It persists the latest Pi session-file pointer and keeps `historyExpected` true once saved history has existed. If expected history disappears, it records the unavailable-history message. Publication follows the catalog write; a write failure faults the session and returns `storage_unavailable`.

<a id="sessions-history-results"></a>

## Saved history, images, and turn results

[`getHistory`](../../../src/sessions/service.ts#L741) uses the bounded read lane. If no Pi session file exists, an active turn whose first history has not materialized may return `pending`; otherwise an expected file that is missing yields `history_unavailable`. A cursor without a file is invalid. The empty response includes active/latest turn IDs and an empty context projection. For an existing Pi session file, the service marks the active turn's history as materialized and calls `HistoryPages.read` with the Dwell session ID, Pi session ID, project directory, cursor, and shutdown signal.

The returned page reconciles visible live output with saved Pi-session content. A durable turn is covered only when storage is healthy, the latest turn is terminal, it has saved entry IDs, and every ID appears on the selected branch. For native executions, expected post-baseline assistant keys come only from a complete file; unknown identity, an oversized diff, or an empty diff blocks coverage. Coverage requires every expected key and the settled leaf on the current branch. With an active observer and a complete read, the service refreshes the next native-execution baseline. The response includes page entries, file revision and leaf, context sources, truncation state, turn IDs, and only proven coverage IDs.

[`getHistoryImage`](../../../src/sessions/service.ts#L857) resolves an image through the validated Pi session file, branch entry ID, and image index within that entry. If expected history is missing it returns `history_unavailable`; if no file was expected or the image is outside the active branch, it returns `null`. [`getTurnResult`](../../../src/sessions/service.ts#L964) accepts only a settled turn. A completed turn with no saved entries returns an empty result; other missing or empty results return `result_unavailable`. It rereads the Pi session file under the history budget, selects the stored entry IDs, and rejects missing IDs. Serialization depth failure or a result over 8 MiB becomes `result_limit`, directing clients to paginated history.

[`#history`](../../../src/sessions/service.ts#L1580) enforces the Pi session-file boundary. Before a file is recorded, it searches only the owning Dwell session directory for a filename matching the Pi session ID and rejects multiple matches. It resolves the file and parent directory, prevents escape from the owner directory, opens with no-follow/nonblocking flags, requires a regular file, and validates the Pi v3 header against session ID and project directory. Missing files return `undefined`; malformed or foreign files become `invalid_history`. [`#savedHistory`](../../../src/sessions/service.ts#L1638) maps an expected-but-missing file to `history_unavailable`, then calls the bounded JSONL reader with optional abort settings. [`#identityForEntries`, `#identityForHistory`, and `#captureHistoryIdentity`](../../../src/sessions/service.ts#L1657) distinguish a complete known baseline, including known-empty history, from an incomplete or unreadable baseline. Caller-requested aborts propagate; other baseline-read failures yield unknown identity and keep live content visible.

<a id="sessions-turn-state-machine"></a>

## Durable turn admission and dispatch

[`submitTurn`](../../../src/sessions/service.ts#L882) first validates the session, request shape and images, then hashes the payload. A repeated `(sessionId, requestId)` with identical content returns the original `TurnInfo` and `created: false`; a different payload is a conflict. New work is rejected if storage is faulted, any local/catalog turn is active, Pi is running native work, or Pi is unconfigured. The service inserts an `accepted` turn before scheduling execution, clears the selected live native-execution projection, installs an `ActiveTurn` slot, publishes the new view, and schedules `#executeTurn` with `setImmediate`. The HTTP acknowledgment confirms durable admission; Pi's final outcome is reported separately.

`#executeTurn` is the central turn transition. It runs the optional internal `accepted` checkpoint, rereads turn/storage state, and records pre-dispatch shutdown as `aborted`. It combines the host shutdown signal with the turn's history-cancellation signal, opens or reuses the Pi process through the mutation queue, and verifies previously expected Pi session history. It rejects images if the active Pi model lacks image support. Before sending, it snapshots saved entry IDs and assistant-message identity counts as the reconciliation baseline.

The dispatch order is deliberate: atomically persist the turn as `dispatching` together with `historyExpected: true`; publish and run the `dispatching` checkpoint; reread turn/storage; honor cancellation or shutdown; begin the live event projection; subscribe as a passive observer; call `PiProcess.startRun`; mark the slot dispatched; then await prompt acceptance. A `handled` acceptance detaches the turn's observer because extension-owned follow-up is tracked as a native execution. A `started` acceptance persists `running` and runs the running checkpoint. After settlement, it waits for any shared abort, refuses to treat a failed cancellation as certain, and routes an extension-handled input through `#completeHandledTurn`. Ordinary settled execution refreshes history, records the newly observed Pi entry IDs, updates the turn to the Pi outcome, and stores a provider error only for a failed outcome.

On an exception, the turn becomes `aborted` only for known shutdown before dispatch. A correlated `prompt` rejection is known and becomes `failed`; a dispatched error without that rejection becomes `interrupted`, while other failures become `failed`. `SessionError` always keeps its stable code and message. Other errors use `outcome_unknown` after dispatch unless Pi explicitly rejected the prompt, and `execution_rejected` before dispatch or for a correlated rejection. The post-dispatch code records that Pi may already have acted. If outcome persistence fails, `#storageFault` marks the session. The Pi process stops after dispatch failure or storage fault. In `finally`, a canceled first turn that did not dispatch clears speculative `historyExpected`; outstanding aborts are observed, the matching slot is removed, the live projection ends, and durable state is published. Prompt replay is never automatic.

[`#completeHandledTurn`](../../../src/sessions/service.ts#L1326) handles extensions that consume input without an ordinary model turn. It checks Pi still reports the stored session, gathers the current session file and selected model/thinking, reads history if it exists, and records only entries added since admission. It persists session metadata before completing the turn; a failed save faults storage and prevents an unrecorded completed outcome. [`getTurn`](../../../src/sessions/service.ts#L958) returns the public stored turn after admission/storage checks; callers use `turnView` to omit the private payload identity from the stored record.

<a id="sessions-cancellation-and-native-execution"></a>

## Cancellation and native Pi execution

[`abortTurn`](../../../src/sessions/service.ts#L1014) checks the run ID and returns terminal turns unchanged. A nonterminal turn must have the matching in-memory execution slot. Cancellation intent is saved first: an undispatched turn becomes `aborted` immediately; a dispatched turn retains its status until Pi settles. A dispatched turn calls `#abortRuntime`; an undispatched turn cancels history preparation. If saving cancellation fails, the service faults storage and stops the owning Pi process. [`#abortRuntime`](../../../src/sessions/service.ts#L1124) coalesces repeated aborts per slot, marks `abortFailed` and stops the Pi process when the abort command rejects, and attaches an immediate rejection observer for shutdown-triggered calls.

[`abortNativeExecution`](../../../src/sessions/service.ts#L1049) targets the current native-execution ID. It rejects malformed, stale, and non-running IDs; a Dwell session ID alone does not identify a native execution. The service confirms the Pi process reports the same execution, shares an in-flight abort promise, and stops the process if Pi rejects the abort request. If both cancellation and process stop fail, it returns `native_abort_failed`.

[`#observeRuntime`](../../../src/sessions/service.ts#L1686) registers three observer lanes: process-state changes publish Dwell session state; native-execution notices update the ephemeral session view (a run already active at attachment is marked file-baseline-only); passive Pi records feed live projection only while that Pi process reports native execution. Its disposer removes listeners, drops a baseline owned by the process, and blocks settled-native coverage when an incomplete baseline can no longer be recovered. Observer exceptions do not own or stop the Pi process.

[`#nativeExecutionEvent`](../../../src/sessions/service.ts#L1720) handles start and settlement. Start events are idempotent for the same running ID; a new record snapshots a known history identity, begins a separate native event projection, and publishes state. If a Dwell turn's live counts are available they replace a stale file baseline; otherwise an unknown/ambiguous baseline blocks coverage. Settlement records Pi's outcome with a 2,048-byte error cap, ends the live projection, and derives expected assistant identities only when the live identity remained complete and had no unidentified messages. It updates the known message counts, queues saved-history verification, and requests a Pi-state refresh. `SessionService` tracks these native executions in memory and projects them into session state; they are not durable turn-ledger rows.

[`#refreshNativeHistory`](../../../src/sessions/service.ts#L1806) reads saved Pi-session history with shutdown-aware queue semantics and updates coverage only while the same native execution remains settled and its process observer stays attached. It derives expected message keys from the baseline when possible and refreshes the next baseline only from a complete file. [`#scheduleNativeStateRefresh`](../../../src/sessions/service.ts#L1831) keeps at most one refresh loop per session; later settlements replace one pending request. Its nested `run` callback drains the latest request and always removes its tracked promise. [`#refreshNativeSessionState`](../../../src/sessions/service.ts#L1861) reads Pi state and applies it only if the same process/execution remains current, the session/model has not changed during the read, and Pi confirms the same session. Confirmed model/thinking changes are saved; a storage failure faults the session. Other observer failures do not change the settled execution outcome.

<a id="sessions-shutdown-and-private-helpers"></a>

## Shutdown and state helpers

[`shutdown`](../../../src/sessions/service.ts#L1377) is idempotent. It stops new admissions, marks/aborts pre-dispatch turns, aborts the shared history signal, and waits for queued mutations. It then records cancellation intent, starts aborts for dispatched work, stops Pi child processes concurrently, and waits for slot cleanup. It detaches observers, clears process maps, closes the event hub, drains admitted reads, native refreshes, and discovery promises, then closes SQLite. It reports an error if any Pi-session metadata could not be saved. [`#checkStorage`](../../../src/sessions/service.ts#L1101) rejects turn-state changes after a session storage fault. [`#writeTurn`](../../../src/sessions/service.ts#L1110) combines catalog update with event publication and turns write failures into sticky storage faults.
