# Session service

English | [简体中文](../../i18n/zh-CN/handbook/implementation/sessions.md)

[Implementation index](README.md) · [Session overview](../sessions-storage.md) · [System flow](../system.md)

`SessionService` is the host-side coordinator for durable Dwell identities, one Pi process per open session, saved-history reads, durable turns, native Pi executions, and event publication. It does not own Pi's conversation transcript: it validates and reads Pi's native session file, while the catalog stores session metadata and turn outcomes. The current session/turn/execution concepts remain the implemented API; Thread / Run / Schedule is a separate design direction.

<a id="session-identity-and-recovery"></a>

## Identity, startup, and recovery

[`SessionError`](../../../src/sessions/service.ts#L55) carries an HTTP status and stable error code with its message. [`SessionService.constructor`, `SessionService.create`, and `SessionService.runtimeCount`](../../../src/sessions/service.ts#L231) establish the service. `create` prepares the private data directory, opens `SessionCatalog`, validates every stored session and turn before recovery, marks leftover `creating` sessions interrupted, and marks nonterminal turns interrupted. If validation or reconciliation throws, it closes the catalog before rethrowing. The runtime count is the number of live child-process objects, not the number of catalog records.

The module-level helpers provide the identity and view rules used by that lifecycle:

| Declaration | Behavior |
| --- | --- |
| [`turnPayloadIdentity`](../../../src/sessions/service.ts#L81) | SHA-256 of message text when there are no images; otherwise hashes a versioned object containing the text and image type, MIME type, and data in order. It distinguishes same-key retries with different attachment payloads. |
| [`validateStored`](../../../src/sessions/service.ts#L93) | Rejects invalid Dwell/request/Pi session IDs and non-absolute stored directory or session-file paths as catalog corruption. |
| [`isMessageAfterBaseline`](../../../src/sessions/service.ts#L147) | Parses `digest:occurrence` and accepts only a lowercase SHA-256 digest with a safe occurrence strictly greater than the stored count. |
| [`messageKeysAfterBaseline`](../../../src/sessions/service.ts#L159) | Computes saved assistant-message identities newer than a baseline. It returns `undefined` above 1,024 identities so later coverage checks fail closed. |
| [`messageKeyDelta`](../../../src/sessions/service.ts#L169) | Expands digest-count differences into occurrence keys; a regressed count or a result above 1,024 returns `undefined` rather than guessing. |
| [`turnView`](../../../src/sessions/service.ts#L183) | Removes the private payload digest before a stored turn is exposed as `TurnInfo`. |
| [`active`](../../../src/sessions/service.ts#L188) | Defines `accepted`, `dispatching`, and `running` as nonterminal turn statuses. |
| [`truncateUtf8`](../../../src/sessions/service.ts#L192) | Truncates by Unicode code point while enforcing a UTF-8 byte ceiling, used for native execution error text. |

`SessionService.constructor` snapshots the supplied environment (or the host environment), extension paths, clock, and internal checkpoint callback. Its maps separately track runtimes, observers, history identity, native executions, coalesced native state refreshes, active turns, and storage-faulted sessions; the catalog remains durable while these maps hold live runtime and coordination state. [`configure`](../../../src/sessions/service.ts#L259) is serialized with other mutations, refuses changes while a runtime or turn exists, verifies the absolute Pi configuration, normalizes verification failures to `invalid_runtime`, then saves the verified paths.

[`#configuration`, `#admit`, `#mutate`, and `#read`](../../../src/sessions/service.ts#L1446) define the service's admission and concurrency boundaries. `#admit` rejects new operations once shutdown starts. `#mutate` chains mutations through one promise queue and resets the tail after either success or failure, so a rejected mutation does not poison later queued work. `#read` admits at most two service-level history/result reads, tracks them for shutdown, maps `HistoryReadError` to `SessionError`, and translates shutdown-triggered `AbortError`. The lower-level native-history scanner has its own process-wide two-active/eight-waiter budget, described in [History](history.md#history-scan-budget).

## Directory and model discovery; event subscription

[`listSessions` and `getSession`](../../../src/sessions/service.ts#L282) synchronously admit a read and map catalog rows through `#view`. [`listDirectories`](../../../src/sessions/service.ts#L292) defaults an omitted path to the host home directory (`HOME`, or `USERPROFILE` on Windows); if no home is available it returns `home_directory_unavailable`. Discovery errors retain their public status/code, while unrelated filesystem errors propagate.

[`listAvailableModels`](../../../src/sessions/service.ts#L315) requires saved runtime configuration and coalesces concurrent global discovery into one promise. The shared promise exists only while discovery is in flight and clears on resolution or rejection. [`listSessionModels`](../../../src/sessions/service.ts#L340) requires a stored, non-faulted session with a ready/running runtime. It coalesces reads by runtime object, then checks that the same runtime is still open before returning. Pi or parse failures become `model_discovery_failed`. [`getSessionModelCapabilities`](../../../src/sessions/service.ts#L383) validates a provider/model request, requires an exact match in the active session's registry, and returns only provider, model ID, image support, and thinking levels. [`getModelCapabilities`](../../../src/sessions/service.ts#L403) performs isolated global discovery, coalesces identical provider/model pairs, and admits at most two distinct checks; excess distinct checks return `model_discovery_busy`.

[`subscribeEvents`](../../../src/sessions/service.ts#L442) builds a current session view and current/latest turn projections from durable state before asking `SessionEvents.connect` to register a listener. It translates malformed cursor, per-session/global subscriber overflow, and stream-capacity errors into `invalid_cursor`, `subscriber_limit`, and `stream_unavailable`. [`#publishState`](../../../src/sessions/service.ts#L473) publishes a session-only or session-plus-turn view. Because publication is observation after state mutation, a projection failure is converted to a bounded `state_unavailable` stream error instead of undoing the saved mutation. [`#storageFault`](../../../src/sessions/service.ts#L496) marks a session once in process memory and sends `storage_unavailable` to its stream; later durable turn operations reject until the host is restarted after repair.

<a id="sessions-create-open-close"></a>

## Create, open, close, and select a model

[`createSession`](../../../src/sessions/service.ts#L506) runs inside the mutation queue. It validates a request UUID, absolute directory and all-or-none provider/model pair before hashing the original request payload. It looks up the request key before touching the directory, so a retry can still resolve after the original directory has disappeared; a different payload under the same key is a `request_conflict`. For a new key it verifies configuration and canonicalizes the directory with `#directory`, prunes exited children, enforces the eight-open-runtime limit, inserts a `creating` row, and only then launches Pi. A successful launch returns `ready`; a startup exception is recorded as `failed` and returned as a session view. The durable pre-launch insert lets startup recovery distinguish abandoned creation from a missing record.

[`openSession`](../../../src/sessions/service.ts#L694) serializes a call to `#open`. `#open` reuses an already-ready runtime, rejects a running one, prunes dead children, checks capacity/configuration and confirms the saved directory still resolves to the same canonical path. If saved history was expected but no longer exists, it records the unavailable-history error and refuses to start a new empty Pi transcript. Otherwise it captures a complete history identity baseline, launches Pi with either the validated resume file or the stored Pi session ID, and supplies a saved provider/model only when creating a new transcript. It verifies the returned Pi session identity, model, and session file. A resumed transcript's native model and thinking state are adopted; for a new transcript, a stored thinking level may be restored when no native execution is already active. Only after these checks does the service save `ready` metadata. Any post-launch mismatch or catalog write failure stops Pi, unregisters observers, and removes the runtime from the map.

[`setSessionModel`](../../../src/sessions/service.ts#L587) accepts only a valid request for a `ready`, idle session. An exact already-selected pair is a no-op unless a different thinking level was supplied. It opens/reuses Pi, checks pre-change state, sends `set_model` only if necessary, optionally sets thinking, then reads Pi state again to confirm the session and selected model. It persists the confirmed provider/model/thinking values before returning. A known Pi `set_model` rejection for an unavailable model or missing API key becomes `model_unavailable`; other unconfirmed outcomes stop the runtime and return `model_change_failed`. If persistence fails after Pi changed, the service also stops Pi so an unrecorded selection cannot keep running.

[`closeSession`](../../../src/sessions/service.ts#L698) refuses an active Dwell turn or Pi run. Before stopping the runtime, it remembers the current native session-file pointer and history-expectation state; a settled native execution with a baseline also gets a history coverage refresh. It then stops Pi, detaches listeners, deletes the runtime mapping, and returns the durable session view. [`getContext`](../../../src/sessions/service.ts#L729) opens the session, requests Pi's current model context messages, refreshes saved-history metadata, and returns them. These are Pi's working-context messages; use `getHistory` for the saved branch.

[`#directory`](../../../src/sessions/service.ts#L1553) requires an absolute, existing directory and returns its `realpath`; all failed or non-directory paths become `invalid_directory`. [`#prune`](../../../src/sessions/service.ts#L1569) stops and releases runtimes already in `failed` or `exited`, detaches their observers, and publishes the changed view before a new runtime consumes capacity. [`#view`](../../../src/sessions/service.ts#L1514) validates its stored input and maps durable plus live state to public `SessionInfo`: startup/stopping become opening/closing, ready/running become ready, a failed runtime remains `failed`, and absent/exited runtimes become `closed`. It derives history state from the durable expectation/error, masks storage-fault details with a stable repair message, and adds native execution and active/latest turn IDs. [`#stored`](../../../src/sessions/service.ts#L1506) validates the Dwell session ID, existence, and stored identity; [`#storedTurn`](../../../src/sessions/service.ts#L1093) does the equivalent for a run ID and its owning session.

[`#rememberHistory`](../../../src/sessions/service.ts#L2020) skips failed/exited runtimes, reads current Pi state, combines its session-file path with the latest catalog record, and asks `#history` whether the file is valid. It then persists the latest file pointer and keeps `historyExpected` true once history has existed; if expected history disappeared, it records the unavailable-history message. It publishes only after saving. A catalog failure marks the session storage-faulted and returns `storage_unavailable` so a close/context operation cannot imply the metadata was safely retained.

<a id="sessions-history-results"></a>

## Saved history, images, and turn results

[`getHistory`](../../../src/sessions/service.ts#L741) uses the bounded read lane. If no Pi file exists, an active turn whose history has not materialized may return `pending`; otherwise a session with `historyExpected` fails with `history_unavailable`. A cursor without a history file is invalid. The empty response includes active/latest turn IDs and an empty context projection. For an existing file, the service marks the active turn's history as materialized and calls `HistoryPages.read` with session, Pi identity, directory, cursor, and shutdown signal.

The returned page is also the evidence used to reconcile visible live output with saved content. A durable turn is covered only if storage is healthy, the latest turn is terminal, it has saved entry IDs, and every ID appears on the saved active branch. For native executions, the service derives post-baseline assistant message keys only from a complete file; it blocks coverage when identity is unknown, the diff exceeds the cap, or the diff is empty. A settled execution is covered only when every expected identity is present on the current branch and its settled leaf remains on that branch. With an active observer and a complete read, the service refreshes the identity baseline for the next native run. The response contains page entries, native revision and leaf, context sources, truncation state, turn IDs, and only proven coverage IDs.

[`getHistoryImage`](../../../src/sessions/service.ts#L857) resolves an image by the session's validated saved file, branch entry ID, and per-entry image index. If history is expected but missing it returns `history_unavailable`; if no history was expected, or the requested image is not on the active branch, the result is `null`. [`getTurnResult`](../../../src/sessions/service.ts#L964) accepts only a settled turn. A completed turn with no saved entries returns an empty result; other empty or missing saved results return `result_unavailable`. It rereads native JSONL under the history budget, resolves precisely the stored entry IDs, and rejects missing IDs. A JSON serialization depth failure or result over 8 MiB becomes `result_limit`, directing clients to paginated history.

The history boundary is enforced by [`#history`](../../../src/sessions/service.ts#L1580): when a session has not yet recorded that history exists, it searches only its Dwell-owned session directory for a filename matching the Pi session ID and rejects multiple matches. It resolves the file and containing directory, rejects escape from the owner directory, opens with no-follow/nonblocking read flags, requires a regular file, and validates the Pi v3 header against session ID and working directory. Missing files return `undefined`; malformed or foreign files become `invalid_history`. [`#savedHistory`](../../../src/sessions/service.ts#L1638) applies the stronger rule that an expected-but-missing file is `history_unavailable`, then calls the bounded JSONL reader with optional abort settings. [`#identityForEntries`, `#identityForHistory`, and `#captureHistoryIdentity`](../../../src/sessions/service.ts#L1657) distinguish a complete known baseline (including known-empty history) from an incomplete or unreadable baseline. A caller-requested abort propagates; an ordinary baseline read failure yields unknown identity and keeps live content visible.

<a id="sessions-turn-state-machine"></a>

## Durable turn admission and dispatch

[`submitTurn`](../../../src/sessions/service.ts#L882) first validates the session, request shape and images, then hashes the payload. A repeated `(sessionId, requestId)` with identical content returns the original `TurnInfo` and `created: false`; a different payload is a conflict. New work is rejected if storage is faulted, any local/catalog turn is active, Pi is running native work, or Pi is unconfigured. The service inserts an `accepted` turn before scheduling execution, clears the selected live native-execution projection (the old run remains in Pi's saved history), installs an `ActiveTurn` slot, publishes the new view, and schedules `#executeTurn` with `setImmediate`. The HTTP acknowledgment confirms durable admission; Pi's final outcome is reported separately.

`#executeTurn` is the central state transition. It first runs the optional internal `accepted` checkpoint, rereads the turn and storage state, and records a pre-dispatch shutdown as `aborted`. It combines the host shutdown signal with the turn's history-cancellation signal, opens Pi through the serialized mutation queue, and verifies that previously expected native history remains readable. It rejects image input if the active Pi model lacks image support. Before the send point it snapshots all saved entry IDs and assistant-message identity counts, so later output can be compared with a stable baseline.

The dispatch order is deliberate: atomically persist the turn as `dispatching` together with `historyExpected: true`; publish and run the `dispatching` checkpoint; reread turn/storage; honor cancellation or shutdown; begin the live event projection; subscribe as a passive observer; call `PiProcess.startRun`; mark the slot dispatched; then await prompt acceptance. A `handled` acceptance detaches the turn's observer because extension-owned follow-up is tracked as a native execution. A `started` acceptance persists `running` and runs the running checkpoint. After settlement, it waits for any shared abort, refuses to treat a failed cancellation as certain, and routes an extension-handled input through `#completeHandledTurn`. Ordinary settled execution refreshes history, records the newly observed Pi entry IDs, updates the turn to the Pi outcome, and stores a provider error only for a failed outcome.

On an exception, the turn becomes `aborted` only for known shutdown before dispatch. A correlated `prompt` command rejection is treated as a known rejection and becomes `failed`; a dispatched error without that rejection becomes `interrupted`, while other failures become `failed`. For either status, a `SessionError` keeps its own stable code and message. Only other errors use fallback codes: `outcome_unknown` after dispatch when acceptance was not explicitly rejected, and `execution_rejected` before dispatch or for a correlated prompt rejection. The post-dispatch fallback reflects that external side effects may already have happened. If recording the outcome fails, `#storageFault` marks the session. A dispatched or storage-faulted runtime is stopped. In `finally`, a canceled turn that never dispatched and whose transcript did not previously exist clears the speculative `historyExpected` flag; any outstanding abort is observed, the same slot is removed, the live turn projection ends, and durable state is published. No automatic prompt replay is performed.

[`#completeHandledTurn`](../../../src/sessions/service.ts#L1326) handles extensions that consume input without an ordinary model turn. It checks Pi still reports the stored session, gathers the current session file and selected model/thinking, reads history if it exists, and records only entries added since admission. It persists session metadata before completing the turn; a failed save faults storage and prevents an unrecorded completed outcome. [`getTurn`](../../../src/sessions/service.ts#L958) returns the public stored turn after admission/storage checks; callers use `turnView` to omit the private payload identity from the stored record.

<a id="sessions-cancellation-and-native-execution"></a>

## Cancellation and native Pi execution

[`abortTurn`](../../../src/sessions/service.ts#L1014) checks the requested run and returns terminal turns unchanged. It requires the matching in-memory execution slot for a nonterminal turn. Cancellation intent is durably written first: a not-yet-dispatched turn becomes `aborted` immediately, while an already-dispatched turn keeps its current status until Pi settles. A dispatched turn calls `#abortRuntime`; a pre-dispatch turn aborts history preparation. If persistence fails, the service faults storage and stops the owning runtime so the now-unreliable cancellation route cannot strand execution. [`#abortRuntime`](../../../src/sessions/service.ts#L1124) coalesces repeated abort calls per slot, marks `abortFailed` and stops Pi if the abort command rejects, and attaches an immediate rejection observer because shutdown may initiate it without awaiting.

[`abortNativeExecution`](../../../src/sessions/service.ts#L1049) targets the current native execution ID. It rejects malformed and stale/non-running IDs; a session ID alone cannot select a Dwell turn. It verifies that the runtime reports the same native execution, shares an in-flight abort promise, and escalates to process stop if Pi's abort request fails. If both mechanisms fail, it returns `native_abort_failed`.

[`#observeRuntime`](../../../src/sessions/service.ts#L1686) registers three observer lanes: state changes publish session state; native-execution notices update Dwell's ephemeral native record (marking a run that began before attachment as file-baseline-only); passive Pi records feed live projection only while Pi reports a native execution. Its disposer removes all listeners, drops a baseline owned by that runtime, and blocks settled native coverage when an incomplete baseline could no longer be recovered. Observer exceptions do not own or stop Pi.

[`#nativeExecutionEvent`](../../../src/sessions/service.ts#L1720) handles start and settlement. Start events are idempotent for the same running ID; a new record snapshots a known history identity, begins a separate native event projection, and publishes state. If a Dwell turn's live counts are available they replace a stale file baseline; otherwise an unknown/ambiguous baseline blocks coverage. Settlement records Pi's outcome with a 2,048-byte error cap, ends the live projection, and derives expected assistant identities only when the live identity remained complete and had no unidentified messages. It updates the known message counts, queues saved-history verification, and requests a Pi-state refresh. These native executions are process-local observations, not Dwell turn-ledger rows.

[`#refreshNativeHistory`](../../../src/sessions/service.ts#L1806) reads saved history with shutdown-aware queue semantics and updates coverage only if the same native execution is still settled and its runtime observer remains attached. It derives expected message keys from the baseline when possible and refreshes the next identity baseline only from a complete file. [`#scheduleNativeStateRefresh`](../../../src/sessions/service.ts#L1831) keeps at most one refresh loop per session; additional settlements replace a single pending request rather than creating an unbounded queue. Its nested `run` callback drains the latest request and always removes its own tracked promise. [`#refreshNativeSessionState`](../../../src/sessions/service.ts#L1861) reads Pi state but applies it only if the same runtime/execution is still current, the session/model existed before the read and has not been changed meanwhile, and Pi confirms the same session. A confirmed changed model/thinking level is saved; storage failure faults the session. Other observer failures are ignored because they do not alter the settled execution result.

<a id="sessions-shutdown-and-private-helpers"></a>

## Shutdown and state helpers

[`shutdown`](../../../src/sessions/service.ts#L1377) is idempotent. It stops new admissions, marks and aborts pre-dispatch turns, aborts the shared history signal, then waits for queued mutations before processing active slots. It marks cancellation intent, initiates aborts for dispatched work, stops all child processes concurrently, and waits for each slot's completion cleanup. It detaches observers, clears runtime maps, closes the event hub, drains admitted reads, native refresh work, and discovery promises, then closes SQLite. It reports a final error if any runtime metadata could not be saved. `#configuration` returns the persisted executable/entry-point pair or `runtime_unavailable`; `#checkStorage` rejects further turn state changes after a session storage fault; `#writeTurn` wraps catalog update plus event publication and converts write failures into the sticky storage-fault state.

[`#publishState`](../../../src/sessions/service.ts#L473) publishes best-effort event views after durable writes; [`#storageFault`](../../../src/sessions/service.ts#L496) marks a session faulted and notifies its stream. [`#mutate`](../../../src/sessions/service.ts#L1462) and [`#read`](../../../src/sessions/service.ts#L1476) release their queue or read slot after rejection. [`#stored`](../../../src/sessions/service.ts#L1506) and [`#storedTurn`](../../../src/sessions/service.ts#L1093) validate durable lookups; [`#view`](../../../src/sessions/service.ts#L1514) projects a public session; [`#directory`](../../../src/sessions/service.ts#L1553) canonicalizes a project path; [`#prune`](../../../src/sessions/service.ts#L1569) releases failed/exited runtimes; [`#history`](../../../src/sessions/service.ts#L1580) validates a candidate native file; and [`#savedHistory`](../../../src/sessions/service.ts#L1638) reads expected history under the bounded reader.
