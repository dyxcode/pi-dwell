# 撰写消息并附加图片

[English](../../../../handbook/implementation/compose-message.md) | 简体中文

[实现文档索引](README.md)

<a id="behavior"></a>

## 行为

输入框始终对应当前选中的开放 Pi 会话。消息可以只含文字、只含图片，也可以同时包含两者。图片作为一个有序的独立组随文字一起发送，因此系统不会记录图片在文字中的具体位置。每条消息最多附带 4 张 PNG、JPEG、WebP 或 GIF 图片，解码后的图片总量不超过 5 MiB；文字按 UTF-8 编码后最多 8 KiB。此输入框不接受以斜杠开头的命令。

带精细指针的设备上，Enter 发送消息，Shift+Enter 插入换行；IME 正在组合输入时，Enter 仍由输入法处理。触屏设备使用可见的发送按钮。用户切换开放会话时，每个会话的草稿会各自保留。

<a id="ownership"></a>

## 数据归属

文字草稿和图片草稿只属于当前浏览器页面。文字按会话保存在页面内存中，直到发送得到确认或页面被关闭。图片草稿保留已验证的消息数据和临时浏览器预览地址；选择或粘贴文件时不会向 Host 上传。移除图片会撤销其预览地址。认证失效时，浏览器会清除图片草稿和预览地址。

提交时，浏览器将文字和可选的图片组作为一条轮次 request 发送。Dwell 记录执行身份和状态；Pi 原生会话 history 保存消息与图片。临时预览与之后从已保存历史读取的图片相互独立。

<a id="execution"></a>

## 执行顺序

1. 选中会话时，输入框恢复该会话的文字和图片草稿。客户端会根据当前模型的能力控制图片入口：能力未知或检查失败时不能添加图片；已知不支持图片的模型不能发送带图消息。
2. 选择或粘贴图片后，浏览器为该会话启动一次文件读取。每张图片都会检查媒体类型、转换成适合 JSON 请求的数据，并由浏览器解码后才显示在草稿栏。用户可以预览或移除已接收的图片。
3. 发送时，客户端为当前文字和图片顺序创建一份请求快照及请求身份。空消息、超过 8 KiB 的文字、斜杠命令，以及已知不受当前模型支持的图片组合都会被拦截。Pi 收到轮次前，Host 还会再次验证请求。
4. 收到已确认的响应后，客户端清空该会话的文字和图片草稿，并重新读取保存的对话。如果响应结果不确定，客户端保留同一份请求内容和身份；重试会复用它，Host 因而可以返回原来的已接受轮次，而不会重复创建。收到身份匹配的 live 轮次确认时，也会清除保留的草稿。

<a id="mechanisms"></a>

## 内部机制

图片读取和浏览器解码都是异步操作。每次读取都会记录发起时的会话和页面代次。如果解码完成前用户切换会话、失去认证或图片入口被禁用，迟到的结果会被丢弃，其预览地址也会撤销。某个文件发生错误时，本批次后续文件不再处理；已经加入草稿栏的图片仍会保留。文件选择结束后会重置原生文件输入，因此用户可以再次选择同一个文件。

textarea 使用浏览器原生编辑，保留换行、粘贴、选区和 IME 行为。只有可信、无修饰键、光标折叠且不处于组合输入的 Backspace 才会启用加速；移动光标、选中文字或失焦都会取消长按。如果浏览器支持原生删除操作，持续按住时会逐步加快删除速度；否则继续使用浏览器自己的按键重复行为。

移动端键盘可能先改变 visual viewport，而页面布局稍后才更新。输入框优先使用浏览器原生的内容缩放行为；只有输入框仍被遮挡时才调整页面主体。调整过程中保留对话距底部的间隔：正在跟随最新消息的读者仍停在底部，向上浏览的读者则保持原来的可见位置。

<a id="technology"></a>

## 技术选择

原生 textarea 保留平台的文字编辑、无障碍、撤销和输入法能力。移动端键盘遮挡输入框时，布局会参考 VisualViewport；动画帧将连续的视口变化合并为一次重新计算。输入框按视口比例增长，较长草稿则在输入框内部滚动。

预览使用可撤销的 object URL；实际提交使用经过验证、以 base64 表示的内容，适配 Pi 的 JSON RPC 边界。草稿保存在页面内，避免额外的上传与存储生命周期，但页面关闭后也不会保留。文字与有序图片数组分开，符合 Pi 的消息接口；代价是不能把图片插入文字中间。

<a id="verification"></a>

## 关键场景与结果

纯文字、文字加图片、纯图片都应作为一条用户消息交给 Pi；图片应按选择顺序提交，并在保存历史中保留原始字节。第 5 张图片、不支持的媒体类型、与文件签名不符的图片，以及总量超过 5 MiB 的组合都应被拒绝，同时保留此前已接收的草稿。文字模型应阻止发送图片，但允许用户移除现有图片。

切换会话后应恢复各自的草稿；读取图片过程中切换会话，迟到的图片不能进入另一个会话。结果不确定时重试应使用同一份消息与图片；观察到对应轮次后输入框应清空。移动端键盘打开或关闭时，输入框应保持可见，读者原先的滚动位置应保持稳定。
