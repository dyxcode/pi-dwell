# 历史退休与恢复

[English](../../../../handbook/implementation/history-retirement.md) | 简体中文

[实现文档索引](README.md)

<a id="behavior"></a>

## 行为

Pi 的 native 会话 file 是对话记录。满足 Distill 自身生命周期规则后，Distill 可以删除来源文件。Dwell 会区分这种已完成的退休与普通文件缺失：只有匹配的 Distill 删除回执才能将历史标记为 retired；没有回执时，缺失的文件仍是 unavailable。Pi 对话文件删除后，Dwell 仍保留会话、名称、轮次记录和 Current 引用。

观察到历史退休后，Dwell 会使对话记录投影、历史分页分页游标和已保存图片预览失效。恢复有效的原生文件后，该会话重新变为可读状态，浏览器会重新加载所选对话。替换文件产生了新的来源代次时，不会沿用旧代次的退休结果。

<a id="ownership"></a>

## 数据归属

Pi 拥有 native conversation file；Distill 拥有来源代次、清理流程和已完成删除的回执。Dwell 记录观察到的文件、对应的来源代次与删除意图，以及会话的历史状态。浏览器只持有临时对话记录投影和图片预览；Host 报告历史退休后，浏览器会丢弃这些视图。

Dwell 保护两种不同的来源访问。短时读取租约覆盖一次 history read 和回执查询；持久的 Host 使用预留覆盖托管 Pi 子进程的整个生命周期。来源协调中的预留由 Distill 持有；Dwell 负责在访问前创建它、进程启动后关联实际子进程，并且只在确认子进程关闭后释放。

<a id="execution"></a>

## 执行顺序

1. 读取已保存历史前，Dwell 会针对 Pi 会话、文件和工作目录向 Distill 获取短时读取租约。它读取原生文件，并在释放租约前查询是否有已完成的删除回执。
2. 重新打开已保存会话或启动全新的 Pi 进程前，Dwell 会创建持久使用预留。子进程启动后，Dwell 将实际进程身份关联到预留。直到确认该子进程关闭，预留才会释放。
3. 如果读取时发现文件缺失，Dwell 会向 Distill 查询同一会话、路径和来源代次的完成回执。匹配回执表示历史已退休；没有匹配回执时，原本预期存在的历史会标记为 missing。
4. 退休状态会发布给浏览器；浏览器丢弃已保存内容投影和图片预览，并重新请求当前历史状态。若有效文件已恢复，成功读取会将状态记为 readable，再次加载对话。

<a id="mechanisms"></a>

## 内部机制

单凭文件缺失不能证明历史已退休。回执必须已完成，并与来源会话、文件路径和准确代次相符。Dwell 会记住上次观察到的删除意图，因此恢复的文件后来被手动删除时，同一份旧回执不会再次将它判为 retired。观察到新的来源代次后，旧删除意图会清除；该代次下若文件缺失，在自己的回执匹配前仍是 missing。Host 重启后，只要文件仍缺失且来源代次未变，既有 retired 状态会继续显示，即使 Distill 暂时不可用也如此。

History read 可能并行。只有最新启动的检查可以提交结果。如果较早检查在更新观察提交后才结束，它会按最新已提交状态完成；仍在等待的较新检查不会抹掉当前已保存的结果。读取租约被占用时，Dwell 也不会把协调冲突转换成 missing 或 retired。

持久使用预留与短时读取租约相互独立，因此开放的 Pi 子进程不会长期占用 history read gate。重新启动 Host 后，只有 Distill 确认准确的子进程已经退出，才能回收已关联进程的预留。确认从未启动子进程的 opening 可以放弃；启动情况不明时则继续保留。释放失败会留待关闭流程重试；尚未关闭的子进程仍保有预留。

<a id="technology"></a>

## 技术选择

短时租约在 Distill 清理过程中协调文件读取，而不会在交互式进程的整个生命周期锁定来源。持久使用预留则单独告知 Distill：托管 Pi 子进程仍在使用来源。两者共同保护读取与重新打开，同时让一般的有界历史读取继续进行。

来源代次与完成回执共同区分有意清理、手动丢失和文件替换。Dwell 保留执行身份和状态；Pi 仍拥有对话内容，Distill 负责来源保留规则。文件恢复后仍由 Pi 持有原生历史，并沿用原来的当前分支读取方式。

<a id="verification"></a>

## 关键场景与结果

Distill 为准确来源代次完成清理后，Dwell 应显示 retired history，使旧分页分页游标失效，清除对话记录和图片缓存，同时保留会话名称、轮次记录和 Current 引用。没有匹配回执的手动文件删除应显示 missing history。

恢复有效文件后，会话应重新显示 readable history，浏览器也应重新载入对话。没有新回执时再次删除该文件仍应是 missing；替换来源代次不能继承较早的退休回执。Host 重启后，仍在运行的 Pi 子进程应继续持有使用预留，直到确认准确的进程已退出。并行检查应以最新已提交观察为准；Distill 租约繁忙时不能误报退休。
