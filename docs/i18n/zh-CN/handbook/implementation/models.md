# 目录与模型选择

[English](../../../../handbook/implementation/models.md) | 简体中文

[Implementation handbook](README.md) · [Documentation](../README.md)

<a id="behavior"></a>

## 用户行为

创建会话时，从 Host 上选择现存目录作为 Pi 项目。目录选择器从用户主目录 开始，只显示可见子目录并返回规范路径。它会跳过隐藏项和文件，将目录符号链接解析到实际目标；扫描超过 10,000 项或列出 500 个目录时会截断结果。

模型发现有两个范围。会话打开前，可查看用户 Pi 配置目录中的全局模型。会话打开后，会从 Pi 实际加载的模型注册表 取列表，包括已加载 extension 提供的 provider。能力 说明图像支持与 thinking level。浏览列表不会改变当前选择。

<a id="ownership"></a>

## 模块职责与数据

项目目录由 Host 文件系统持有；Dwell 将规范路径与会话身份一起保存。Pi 以该目录作为工作目录，并应用自身的 project-trust policy。

Pi 拥有模型注册表 和有效模型/thinking 状态。Dwell 只公开 provider/模型身份，以及当前模型的图像与 thinking 能力；凭据和私有注册表配置留在 Pi 内。Catalog 保存 Pi 确认过的选择；重新打开原生对话记录时，以 Pi 保存的有效状态为准。

<a id="execution"></a>

## 执行流程

1. 目录选择器将请求路径解析为现存目录。创建会话时再次校验并保存规范位置；重开时确认它仍解析到同一位置。
2. 全局模型列表会创建私有临时 Pi 工作区，验证可执行文件，只复制所需Pi 配置，并在 离线模式 下请求 Pi 返回模型列表。完成后删除工作区。
3. 全局能力查询在单独的临时 Pi RPC 会话中以 离线模式 运行，确认目标模型后读取 thinking level 和图像支持。同一查询会复用结果，同时最多运行两种不同查询。
4. 会话模型列表要求 Pi 进程已打开。它读取当前注册表，不切换模型，也不打开已关闭会话。结果对应 注册表中的确切模型。
5. 修改模型要求会话空闲。Dwell 通过 Pi 应用选择，读取有效状态并只保存已确认的值。Pi 可能下调请求的 thinking level。只有 当前模型支持图像时才接受图像输入。

<a id="mechanisms"></a>

## 内部机制

目录结果包含规范化的根目录和子目录。隐藏名称、文件、失效链接、无权限子目录和指向文件的链接会跳过。目录符号链接会解析到目标，因此 Pi 使用的路径也会被保存。如果已保存路径后来解析到不同位置，重开会停止，不会换用其他项目。

全局发现不加载用户会话、extensions、MCP、skills、prompts、themes、上下文文件 或项目内容。它只将允许的Pi 配置复制到当前用户独占的临时工作区，并强制 Pi 离线运行。能力 查询使用相同隔离方式，并清理临时文件和 Pi 进程。缺少可选配置目录文件允许继续；配置错误或 Pi 输出不支持时不会返回部分列表。

Pi 以格式化表格输出全局模型。Dwell 只接受预期表格布局，并提取可公开的模型信息。标题变化、行格式错误、模型身份重复或 Pi 版本不支持都会被拒绝。会话内发现使用实时 RPC 注册表，因此 extension 模型会在加载后出现。

Thinking level 因模型而异。Pi 标记为不可用的 level 会被省略；扩展 level 需要 注册表明确支持。没有 reasoning 的模型只提供 off。Pi 拒绝或无法确认模型更改时，Dwell 会停止运行实例，避免进程继续运行但 Catalog 已过期。

<a id="technology"></a>

## 技术取舍

全局发现使用 Pi 离线运行 CLI；打开中的会话使用 Pi RPC。前者让用户可以在 对话开始前查看已配置模型，后者反映活跃注册表，包括 extension provider。全局发现依赖 Pi 的格式化输出和固定版本，因此严格解析能暴露格式变化。

私有临时配置目录让探测复用 Pi 模型与认证配置，同时不加载保存的会话或项目资源。离线模式 不会调用 provider。查询现有运行实例可避免启动第二个 Pi 进程，并返回准确模型的能力。两种路径都使用 Pi 自己的注册表。

<a id="verification"></a>

## 验证场景

- 目录符号链接会解析到实际目标。隐藏项、文件、失效链接和指向文件的链接会省略；无效目录会失败，列表过大时标记截断。
- 全局离线发现可列出 合成模型，不改写来源配置目录，也不加载 extension。无模型时返回空列表；格式变化或错误表格会被拒绝。
- 已加载 extension 提供的模型会出现在对应活跃会话中，且不改变当前选择。查询关闭会话不会自动重开。
- 能力 结果与请求中的 provider/模型一致，只公开支持的 thinking level 和图像能力，不调用 provider。
- 活跃工作期间更换模型会被拒绝。空闲时更换会保存 Pi 确认的模型和有效 thinking level，重开后仍保留，且不改写全局 Pi 设置。
