# 阅读对话

[English](../../../../handbook/implementation/read-conversation.md) | 简体中文

[实现文档索引](README.md)

<a id="behavior"></a>

## 行为

对话视图由 Pi 保存的当前分支与本次执行的临时视图组成。已保存历史是权威记录；工作进行时会显示 live message 和 tool 状态，对应内容写入保存历史后，临时副本会逐项消失。显示文字相同并不代表两条消息相同。

侧边栏列出会话；仍处于开放状态的 Pi 会话也会显示为编号标签页，关闭前编号保持不变。用户消息各自形成一轮；同一轮中的 assistant 文字、thinking、tool 调用和结果、extension 消息与 history 内的上下文会连续显示，直到下一条用户消息。项目指令的保存快照则置于对话前的独立 Context 面板。连续的 thinking 和 tool 步骤合并为一条默认折叠的活动行，样式与单个工具步骤一致。运行时，有可用信息就显示当前的 thinking 步骤或正在运行的工具。总步数固定在右侧，有失败时也会显示失败步数。展开后可查看各步骤，具体输出仍需单独打开。Assistant 正文按原顺序显示，不会收进摘要。较早历史按页加载。

<a id="ownership"></a>

## 数据归属

Pi 拥有 native 会话 file、分支结构、已保存消息和模型上下文。Host 读取并验证所选分支的快照，再投影为有界页面供浏览器显示。项目指令以 Pi history 中保存的快照显示，页面不会重新读取工作目录中的当前文件。

浏览器只负责当前渲染结果、live stream 状态、折叠面板、焦点和滚动位置。已保存图片通过所属历史条目及图片位置单独读取，避免每次加载对话记录时复制图片字节。更换所选会话时，该会话的历史、事件流和图片读取任务会一起切换。

<a id="execution"></a>

## 执行顺序

1. 选择开放会话后，客户端清理上一会话的视图，同时读取最新历史页面并开始观察同一会话。选择变化会使上一会话尚未完成的读取失效。
2. Host 从 Pi 保存的末条记录沿 parent 链找到当前分支，再按时间顺序投影消息、组合响应条目，并随页面返回上下文快照和更早内容的分页游标。
3. Live event 更新当前消息和 tool 投影。重连、收到 snapshot 或 resynchronization 时，浏览器会重新读取已保存历史并与 live 状态协调。已保存的最终结果会替换相应的 live 内容，而不是重复追加。
4. 打开更早页面时，页面内容插入对话顶部。浏览器保持原先可见消息在屏幕上的位置；如果读者原本已在底部，新响应内容会继续跟随最新输出。

<a id="mechanisms"></a>

## 内部机制

Saved assistant 身份来自完整的 Pi 原生消息及其出现次序，而不是可见文字。这样既能保留重复但内容相同的消息，也能让已完成的 live message 与其保存版本衔接。Tool 调用记录所属 assistant 身份；即使中间出现其他 Pi 条目，仍按调用身份与结果配对。孤立的结果和没有保存结果的调用都会显示说明，不会静默消失。

Markdown 会解析为明确创建的 DOM 元素。Raw HTML 显示为普通文字；链接只允许 HTTP、HTTPS 和 mailto 目标；Markdown 图片则显示为文字标签，不会自动获取图片。代码、表格、列表、标题和强调保留各自结构。Thinking disclosure 默认折叠；符合长度条件的短标题可作为面板名称，完整内容留在面板内。

响应组和重要控件都有稳定的 DOM 身份。协调更新会复用兼容节点，只重绘发生变化的保存组，并保留 disclosure 状态。若焦点所在的 tool summary 必须替换，焦点会回到身份相同的新节点。流式更新时，只有原本距底部不超过 90 像素才会继续自动跟随；否则最近的可见消息锚点会保持阅读位置。

每个历史页面最多包含 100 条投影条目或 240 KiB 页面内容。Continuation 固定在同一原生文件 revision 上，因此新追加内容不会移动旧页面的边界。Host 重启后旧分页游标失效；重新请求最新历史会建立新的分页边界。

<a id="technology"></a>

## 技术选择

直接读取 Pi 的 native JSONL 和分支链，避免另建对话记录格式，也保留 Pi 自己的对话语义。Host 生成有界投影，避免一次读取过大的历史；native 身份则防止 live 输出与已保存内容重复。Markdown parser 提供语法树，再由客户端显式创建 DOM 节点，避免把不可信消息文本作为可执行 HTML 插入页面。

Keyed DOM reconciliation 与响应组缓存保留整体重建时容易丢失的浏览器状态，包括已打开的 tool 详情、thinking 面板、键盘焦点和图片回调。要让这些状态跨 live-to-saved 切换保留，实时视图与保存视图必须使用一致的消息和 tool 身份。

<a id="verification"></a>

## 关键场景与结果

两条内容相同的 assistant 消息应继续分别显示；只有已保存的历史中出现身份匹配的 native message，live message 才应消失。Tool result 应跨越中间条目与所属调用配对；孤立结果或缺失结果应有明确说明。

Raw HTML 应显示为普通文字，不安全的链接目标不应变成可点击链接。大量连续步骤折叠时只占一条摘要，正文和失败计数仍然可见。打开的活动摘要、thinking 与 tool 面板应跨流式更新和保存历史衔接保持展开。读者停在底部时应跟随新输出；向上浏览时，更新或插入旧页面后仍应看到同一条消息。切换会话时，旧会话尚未完成的 history read 不能显示到新会话中。
