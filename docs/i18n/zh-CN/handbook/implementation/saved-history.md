# 读取 Pi 保存的会话历史

[English](../../../../handbook/implementation/saved-history.md) | 简体中文

[Implementation](README.md) · [Handbook](../README.md)

<a id="behavior"></a>

## 行为

Pi 原生 JSONL 文件是权威对话记录，也是 Pi 重新打开会话时恢复上下文的来源。Dwell 读取该文件，展示当前分支、图片、工具结果和已保存的指令快照。界面显示的历史与模型上下文分开处理。

对话视图沿文件当前 leaf 的祖先链排列；其他已保存分支不出现在当前视图。第一页展示当前分支最新条目，后续页面逐步向祖先方向翻阅。每页最多投影 100 条记录，内容预算为 240 KiB，并为响应元数据留出空间。

视图会投影文本、thinking 内容、工具调用和结果、摘要、上下文编辑及支持的诊断信息。图片数据保存在原生条目中，按需读取。指令快照作为上下文来源显示；超过展示预算的部分会标记截断。

<a id="ownership"></a>

## 所有权

Pi 拥有原生会话文件、分支、已保存消息、图片，以及将分支用于模型上下文的规则。Dwell 的 SQLite 目录保存 Pi 会话身份、原生文件引用、观察到的历史状态、持久化轮次记录，以及已完成轮次对应的原生条目引用；

原生历史读取器会根据预期的 Pi 会话和项目目录验证 v3 header，检查条目标识与 parent 顺序，并投影受支持的内容。分页服务构建当前分支、签署游标并解析图片引用；浏览器再将历史页面与临时实时输出合并。

轮次状态和已保存内容的生命周期不同。SQLite 中的 completed 记录可以继续存在，而原生条目可能已无法读取；被引用的内容仍必须由 Pi 文件提供。

<a id="execution"></a>

## 执行顺序

读取最新历史时，Dwell 定位该会话的原生文件，并读取有界、稳定的快照。它解析完整的 JSONL records，验证 header 和 parent chain，再确定当前 leaf。未完成的末行会被排除，并报告 incomplete tail。读取期间文件身份或内容发生变化时，快照不会被接受。

分页服务从 leaf 沿 parent references 遍历，再反转成对话顺序。它最多投影 100 条条目，并遵守单条与整页预算。有更旧内容时，返回的 signed cursor 会记录会话、byte-prefix revision 和旧页边界。后续读取使用同一前缀，新追加内容不会改变已开始的分页位置。

图片块引用条目及其中的位置，而不携带 base64 内容。读取图片时会确认条目仍属于当前分支，再返回所选的受支持图片。重新打开会话时，Pi 针对已验证的原生文件启动，并由 Pi 自己恢复分支与上下文规则。若原文件或条目缺失，SQLite 引用无法重建内容。

<a id="mechanisms"></a>

## 内部机制

原生文件上限为 128 MiB，每条 JSONL 记录上限为 8 MiB。读取器以不跟随符号链接的方式打开由 Host 用户持有的普通文件，并在读取后确认路径仍指向同一文件。文件身份和 byte prefix digest 将游标绑定到一次观察；前缀变化后，必须重新读取最新历史。

对齐过程会为每条完整的原生 assistant 消息计算 fingerprint，并记录它在文件中的出现次序，因此重复内容仍可区分。工具结果会关联到拥有该工具调用的 assistant 消息。浏览器依据这些原生身份匹配实时输出，不单凭可见文本相同来判断条目已保存。

History 和图片读取共用进程级预算：同时最多运行两次扫描，另有最多八个任务按 FIFO 等待。取消时可移除仍在队列中的轮次准备读取；已准入扫描会完成并释放许可。关闭目录数据库前，Host 会等待已准入读取排空。历史读取位于变更队列之外。

<a id="technology"></a>

## 技术选择

已安装的 Pi RPC 会一次返回全部 saved entries，没有分页。直接读取原生 JSONL 让 Dwell 能限制文件、记录、页面和并发扫描的资源使用，无需通过 RPC 传输整个会话树；Pi 的文件仍是唯一持久化对话记录。

该只读适配器遵循 Pi v3 JSONL layout 和条目 parent 语义。这避免建立第二份对话记录 database，也使文件校验和有界扫描成为历史读取边界的一部分。Signed cursor 不需要对话记录 cache；签名 key 只在当前进程内有效，因此 Host 重启后浏览器会从最新页面重新开始。

<a id="verification"></a>

## 验证场景

读取含有多个分支的会话。页面按对话顺序包含当前 leaf 的祖先链，其他分支的条目不会出现。

翻阅较旧历史时，Pi 又追加了消息。游标继续读取原 byte prefix；若该前缀被替换或修改，页面会失效并要求重新读取最新内容。

切换会话或使历史失效后再加载已保存图片。旧响应不会把图片加入新对话，原生文件读取会确认该图片仍属于当前分支。

多次保存内容完全相同的 assistant 消息，并包含工具结果。每次出现都保留为独立条目，工具结果也会关联到所属的 assistant 消息。

恢复原 Pi 会话文件后重新打开 Dwell 会话。Pi 从该原生文件继续，文件仍是对话记录和模型上下文的来源。
