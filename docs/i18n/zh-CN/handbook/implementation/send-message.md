# 向 Pi 托管会话发送消息

[English](../../../../handbook/implementation/send-message.md) | 简体中文

[Implementation](README.md) · [Handbook](../README.md)

<a id="behavior"></a>

## 行为

发送消息会在所选 Pi 会话中创建一条可持久化的 Dwell 轮次（轮次）。浏览器发送原始文本，以及可选的有序图片集合。文本上限为 8 KiB；一次请求最多包含四张图片，解码后的总大小不超过 5 MiB。请求须包含非空白文本或至少一张图片，Web 输入框不把 slash command 解释为命令。

每次发送都会携带请求标识。若 Host 已接受请求但响应丢失，浏览器会保留标识和完整内容，以便重试时找回原轮次。Host 先按会话查找请求标识，再核对文本和图片内容。标识与内容都相同的重试会返回已有轮次，即使执行仍在进行；相同标识对应不同内容时会被拒绝。新标识代表新的尝试，即使文本看起来相同。

初始响应确认的是持久化准入；之后即使响应已返回或浏览器断开，执行仍会继续。浏览器确认 Host 接受了哪个请求后，才清除草稿和附件。

<a id="ownership"></a>

## 所有权

浏览器管理尚未发送的草稿、附件预览，以及是否已被接受仍不确定的提交。等待确认期间，浏览器会冻结这次提交；重试时继续使用相同内容和请求标识。

HTTP 边界负责身份验证、检查请求大小和内容，并把准入交给会话服务。会话服务用全局变更队列串行处理元数据更新，并用每个会话的活动槽位防止轮次重叠。SQLite 保存请求标识、轮次状态、取消意图，以及指向 Pi 原生历史条目的引用。Pi 负责解释 prompt、运行 extensions、调用模型和工具，并记录结果消息的原生对话记录。事件中心维护实时进度投影，Pi 子进程仍由 Host 持有。

<a id="execution"></a>

## 执行顺序

准入流程会在全局变更队列中再次验证请求。服务先按会话和请求标识查询已有轮次，再比对已保存的内容标识；完全匹配时会在 busy 检查之前返回原轮次。新请求则须满足存储可用、会话空闲、Pi 已配置等条件。之后服务会把已准入轮次写入 SQLite，预留该会话的活动槽位，发布状态，并安排异步执行。

执行进程会打开或恢复同一个 Pi 会话，并根据当前模型检查图片输入能力。发送 prompt 前，Dwell 读取已保存历史，为原生条目标识和 assistant 消息身份建立基线。SQLite transaction 随后记录 dispatch intent，并标明 Pi 历史从此应当存在。真正发送前，服务再次检查取消与关闭流程状态，并先安装 Pi 事件观察器。

Pi 的 prompt 响应会区分普通 agent run 和由 extension 接管的输入。普通 run 先记为已准入，再记为开始发送和运行，最后进入结算。Pi 执行结束后，Dwell 再读已保存历史，找出基线之后新增的条目，并将终态结果及条目引用一并提交。后续读取结果时，再通过 Pi 当前的原生历史文件解析这些引用。如果执行结束后的历史读取暂时繁忙，Dwell 会将该轮次记为中断，不宣称已核实对应的保存条目。回复仍可能出现在已保存的历史中，正常的 Pi 子进程可继续处理下一轮。

<a id="mechanisms"></a>

## 内部机制

请求标识在单个会话内定位重试；另一个内容标识覆盖原始文本和有序图片，用于识别内容是否改变。准入记录先于 prompt dispatch 提交，因此提交失败时不会发送 prompt。

Pi 事件可能早于 prompt 响应。Runtime 在写 RPC 之前安装当前执行状态，并将每个响应关联到对应的待处理命令。Command 超时会让待处理 RPC 失败；若 prompt 已发送，执行结果便可能不确定。预先安装的事件观察器和 saved-history 基线，让 Dwell 能把实时事件与新保存的条目对应起来。

Extension 可以接管输入而不启动普通 assistant response。Dwell 会将该请求结算为 handled，结果只包含 Pi 实际保存的条目。若 extension 随后启动 agent run，它会获得独立的原生执行标识，并与已完成请求分开观察。

Host 重启后，尚未结束的持久化轮次会标记为 interrupted（中断）。Dispatch 尚未开始时，记录可以说明 prompt 未发送；dispatch 之后，工具或 extension 可能已产生效果，结果可能未知。Dwell 不会自动重发 prompt。

<a id="technology"></a>

## 技术选择

Pi RPC 保留已安装的 coding-agent 运行实例，包括其 extensions 和 tools；Dwell 负责子进程与会话协调。关联后的 RPC 响应和异步执行事件分别提供准入与结算信息。

SQLite transaction 保护准入记录和 dispatch intent；长时间的模型执行位于事务和全局变更队列之外。模型运行期间，其他元数据操作和读取仍可继续。原生 JSONL 保存结果内容，SQLite 保存执行状态和条目引用。

<a id="verification"></a>

## 验证场景

请求被准入后浏览器丢失响应，再以相同标识重发相同文本和图片。Host 返回原轮次，Pi 只收到一次 prompt。

两个带相同标识和内容的并发请求最终对应同一轮次。修改内容后沿用该标识会被拒绝；使用新标识则属于新的尝试。

Extension 接管请求，但没有产生普通 assistant response。该轮次以 handled 结算，结果只包含 Pi 保存的条目，extension 启动的后续执行则显示为原生工作。

Dispatch 后发生 restart，轮次保留为 interrupted，且不会 replay。重试会找回已有记录，不会重复可能已经产生的工具效果。
