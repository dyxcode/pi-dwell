# 修改会话名称

[English](../../../../handbook/implementation/session-names.md) | 简体中文

[Implementation handbook](README.md) · [文档目录](../README.md)

<a id="behavior"></a>

## 用户操作

会话名称由 Dwell 保存在 Host 上，所有浏览器共享，重启后仍然存在。用户可以设置名称、修改名称，或通过 Reset 恢复默认显示。

默认名称取自工作目录的最后一级名称。界面会在名称后附加当前模型和 thinking level。自定义名称最多包含 **80 个 Unicode code points**，保存前会去除首尾空白。组合 emoji 可能占多个 code points。空白名称无法保存，Reset 会清除自定义名称。

Import 将旧版浏览器本地名称复制到输入框，点击 Save 后成为共享名称。

<a id="ownership"></a>

## 模块职责与数据

| 部分 | 职责 | 数据及生命周期 |
| --- | --- | --- |
| Browser | 编辑、显示、处理冲突和异步响应 | 草稿、打开时的名称版本、编辑框标记；保存在内存中 |
| Session coordination | 协调修改、确认会话存在、发布更新 | 连接浏览器操作与 Catalog |
| Catalog | 持久化存储和版本检查 | 名称、名称版本和会话更新时间；保存在 SQLite 中 |

Pi 负责执行和维护原生对话历史。改名更新 Dwell 的元数据，对话历史保持原样。名称版本记录改名的先后关系，模型和运行状态变化使用各自的状态处理机制。

<a id="execution"></a>

## 一次保存如何完成

打开编辑框时，浏览器记住当前名称及其版本。输入内容保留为本地草稿。点击 Save 后，浏览器检查名称，将名称和记录的版本发送给 Host，并暂时禁用 Save、Reset 和 Import。

Host 将修改放入协调队列，再在数据库事务中读取已保存的名称和版本。先比较版本，再判断名称是否变化。有变化时保存新名称、推进版本并更新时间。Host 将保存后的状态发布给订阅者，同时返回给发起操作的浏览器；浏览器合并结果并关闭编辑框。

| 条件 | 结果 |
| --- | --- |
| 版本一致，名称变化 | 保存、推进版本并发布更新 |
| 版本一致，名称相同 | 返回当前状态，版本和更新时间不变 |
| 版本过期 | 进入冲突处理，即使提交的名称相同 |
| 名称为空白或超长 | 保留编辑框，提示调整输入 |
| Reset 且存在自定义名称 | 清除名称并推进版本 |
| Reset 且已使用默认名称 | 保持当前版本 |

<a id="mechanisms"></a>

## 并发修改与迟到的响应

**两个浏览器同时编辑。** 两边打开时都是版本 4。第一个保存后版本变成 5；第二个仍提交版本 4，因此被拒绝。这是 optimistic concurrency control／乐观并发控制：允许同时编辑，保存时检查修改依据。

发生冲突后，浏览器读取最新名称、更新显示并关闭编辑框，未保存的草稿随之丢弃。如果刷新失败，编辑框保持打开并报告错误。

**保存响应迟到。** 浏览器可能先通过 SSE 收到版本 6，随后才收到版本 5 的保存响应。它会保留较新的名称。版本比较保护名称及其版本，响应中的其他会话状态仍参与更新。

**用户已经打开另一个编辑框。** 每次打开都会产生新的编辑标记。响应只有在标记、会话和打开状态仍匹配时才能影响编辑框。关闭编辑框结束本地编辑，已经发送到 Host 的修改仍可能完成。

**历史读取晚于改名完成。** Catalog 的普通更新写入生命周期和历史信息，名称更新单独负责名称及其版本。因此，携带旧会话数据的后台读取会保留刚保存的新名称。

<a id="technology"></a>

## 技术作用与取舍

| 机制 | 作用 | 对设计的影响 |
| --- | --- | --- |
| SQLite transaction | 原子地检查版本、写入名称，并持久化保存 | 版本检查与写入在同一提交边界内完成 |
| Host mutation queue | 安排 Host 内部操作的执行顺序 | 用户编辑期间产生的版本差异仍由版本检查处理 |
| HTTP request | 提交修改并返回结果 | 响应可能晚于较新的实时更新到达 |
| SSE | 向订阅中的浏览器发送共享状态 | 客户端在更新和重连时按版本合并名称 |
| 名称版本 | 记录共享名称修改的先后关系 | 旧名称不能覆盖新名称 |
| 编辑标记 | 将响应关联到本地编辑操作 | 旧操作完成后不会干扰新编辑框 |

<a id="verification"></a>

## 关键验证场景

| 场景 | 预期结果 |
| --- | --- |
| 两个浏览器依据同一版本保存 | 第一次成功，第二次进入冲突处理 |
| 新 SSE 更新先到，旧保存响应后到 | 保留较新的名称 |
| 旧请求结束前打开另一个编辑框 | 新编辑框保留输入和状态 |
| 历史读取与改名交错 | 新名称在历史更新后仍然保留 |
| 保存后重启 Host | 恢复已保存的名称 |
| 比较改名前后的 Pi 历史 | 历史内容一致 |
| 连续 Reset 两次 | 第二次保持原版本 |
| 输入达到或超过长度上限 | 接受上限内的名称，拒绝超长名称 |
